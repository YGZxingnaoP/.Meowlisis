## 1. 结论（一句话）

插件内置一个 **function-calling 演员循环**（Actor）：每回合两次调用——**先调工具问"我讲到哪了、我该说什么"，再开口说**。
稿子只提供三样东西：**要点、锚词、喵呜的台词**；它**不要求你逐字说**，也**不是比对基准**。

```
你说的话 ──ASR（可能听错）──▶ route_text（接住 + 主链闭嘴）
                                │ 入队，立即 return True
                                ▼
                         Actor 线程（单线程队列）
   R1  chat(messages, tools=SHOW_TOOLS, tool_choice=required)
       → show_advance(heard="...", evidence="meaning")
       ← {"now":{要点/锚词}, "speak":{喵呜台词}, "next_expect":{...}}
   R2  chat_stream(messages + tool 结果, tools=None)
       → 「哦？离谱到什么程度？」
       → send_to_answer_queue(句子, traceid, seg_index++, 末段 end)
                                ▼
                             TTS ──▶ 喇叭
```

---

## 2. 为什么闭环必须由插件跑（代码事实）

1. 主链 `LLmCore._ai_response` 的工具调用在**流式正文结束后**丢给独立线程执行（`_dispatch_tool_calls`），
   `role=tool` 结果**不回灌**模型（`analysis.handle_tool_calls` 只写日志）。
2. 所以主链模型调完工具**看不到台词**；它想说稿上的话只能靠提示词记住整份稿——那条路走不通。
3. 仓库里唯一把 `role=tool` 回灌给模型的地方，是**插件自己跑循环**（`docwriter/agent.py` 的 `DocAgent`）。

→ function calling 是对的，**闭环必须插件自己跑**。本方案不依赖导演、不与任何模块协作。

## 3. 稿子是提示，不是台词本（本版核心修正）

### 3.1 三个字段，三种用途

| 文档里的 | 编译成 | 用途 | 是否要求逐字 |
|---|---|---|---|
| `喵呜：台词` | `speak` | 喵呜要说的话 | 近逐字（`fidelity` 控制） |
| `我：内容` | `expect` | 给你看的提示 / 给演员当上下文 | **不要求**，你爱怎么说怎么说 |
| `要点:` / `锚词:` | `intent` / `anchors` | **演员判断"你讲到哪"的主依据** | 否，只作证据 |

写稿时你可以只写要点：

```markdown
喵呜（好奇）：你那天到底几点才到家？
我：讲加班那段（要点：加班到十一点 → 地铁没了 → 走回去）
  锚词: 加班,十一点,地铁,走回去
```

也可以写台词——反正都只是提示，演员不拿它当标准答案。

### 3.2 "你讲到哪了"怎么判（不用文本比对）

演员每回合看到的是**位置 + 要点**，不是"期望你说 X、你说了 Y，相似度 0.3"：

```
你刚说的（ASR 原文，可能缺字/错字/断句）："那天加班到十一电"
上下文：你已经在这一拍讲了 2 句，距上次开口 1.8 秒
主人这一拍要讲的是：加班到十一点，地铁没了，最后走回去
```

判定依据（按优先级）：

1. **语义**——你是不是在讲这一拍的事；
2. **锚词**——`十一点`、`地铁` 这类不怕听错的词有没有出现（听到一两个就够，不要求全中）；
3. **进度**——同一拍你已说了几句、停了多久；看起来讲完了就推进；
4. **显式口语标记**——"然后/接下来/所以说/这事就这样" 这类收尾信号；
5. **前后矛盾**——你说的明显是后面某一拍的事 → 允许在 `lookahead` 内跳过。

**ASR 听错不算脱稿**。演员的硬规则写进系统提示词：

> 主人的话来自语音识别，会缺字、错字、同音字、断句错。**不要逐字比对**，不要复述他刚说的话（可能是错的）。
> 按意思和进度判断；拿不准就 `show_hold(silent=true)` 不出声，等他继续说。

### 3.3 拿不准时：宁可等，不要抢

- `show_hold(silent=true)` → 一声不出，只记一笔（默认）；
- `show_hold(silent=false)` → 用一句"嗯，我在听"占位（你停顿时才用，别打断）；
- 防误推：同一拍内 ASR 连续碎片（间隔 < 400ms、字数 < 6）**不进演员**，只更新上下文。

这条改了 v2 的默认取向：v2 是"宁可推进"，v3 默认**宁可等**（空场可以补，抢错词就崩）。用 `advance_bias` 可切。

## 4. 一回合的时序

```
00:00  你说「今天想聊一个特别离谱的事」（ASR 结果可能还没这么完整）
00:00  route_text
         · 会话激活？是 → 暗号？否 → 回声/去重？否 → actor.submit(text)；return True
00:01  R1（强制工具）
         chat(messages, tools=SHOW_TOOLS, tool_choice="required")
         → show_advance(heard="今天想聊一个特别离谱的事", evidence="meaning")
         ← {"ok":true,"pos":2,
            "speak":{"beat":2,"text":"哦？离谱到什么程度？","emotion":"好奇"},
            "next_expect":{"beat":3,"hint":"让你先猜","anchors":["猜"]},
            "progress":{"scene":1,"elapsed_sec":12,"target":"00:00-03:00"}}
00:02  R2（纯说话，tools=None，流式）
         → 逐句 send_to_answer_queue(text, traceid, seg_index=i, 末段 chat_status="end")
00:02  TTS 出声（音色由 emotion 决定）
```

`tool_choice="required"` 是关键：不强制，模型会跳工具直接开口，位置就乱。
provider 不支持时退回 `auto` + 催一句「先调 show_* 定台位，不要输出正文」（`director/planner.py` 的兜底写法）。

## 5. 工具契约

五个工具，只动内存位置 + 返回台词片段，不碰网络、不碰文件。

| 工具 | 参数 | 说明 |
|---|---|---|
| `show_advance` | `beat`(可选)、`evidence`: `meaning`/`anchors`/`finished`/`skip`/`timeout`、`note` | 前进到下一个「该我说话」的拍 |
| `show_hold` | `silent`(bool)、`reason` | 原地不动；`silent=true` 时不出声 |
| `show_skip` | `count`(默认1)、`reason` | 跳过 n 拍 |
| `show_jump` | `scene` 或 `beat`、`reason` | 跳幕/跳拍（受 `max_jump` 限制） |
| `show_end` | `reason` | 收尾：报告 + 退状态位 |

`show_advance` 返回（模型唯一能看到的稿子内容）：

```json
{
  "ok": true,
  "pos": 14,
  "progress": {"beat": 14, "of": 41, "scene": 2, "elapsed_sec": 252, "target": "03:00-18:00"},
  "speak": {
    "beat": 14,
    "text": "这么晚……那你后来几点才到家？",
    "emotion": "心疼",
    "direction": "声音放轻，别追问太急",
    "pause_after_ms": 300
  },
  "next_expect": {
    "beat": 15,
    "hint": "讲你十二点多到家、地铁停了",
    "anchors": ["十二点", "地铁", "走了"],
    "text": "十二点多吧，地铁都快没了。"
  },
  "preview": [{"beat": 16, "who": "meow", "text": "…"}],
  "note": "识别可能不准，按意思判断；拿不准就 hold"
}
```

约束：

- **只给眼前一小块**：`speak` + `next_expect` + 1~2 条 `preview`，整份稿永不进上下文；
- **越界校验**：`beat` 必须落在 `pos .. pos+lookahead`，否则 `{"ok":false,"allowed":[13,14,15]}` 让模型重试；
- **位置真值在插件**：模型有判断权，改位置只能通过工具；
- **留痕**：`{ts, tool, args, pos_before, pos_after, latency_ms}` 写 `run.jsonl`，复盘和面板都吃它。

## 6. 出声（TTS）

- **一个 beat 一个 `traceid`**，逐句 `ctx.tts().send_to_answer_queue(text, traceid, seg_index=i, chat_status=...)`，
  末段 `""` + `end`；共享 traceid 才能让 TTS 把这一拍当一个连续任务（音色锁定、不插空）；
- **括号/【】不念**：`（心疼）`、`（歪头）` 是舞台提示，情绪走 `emotion` 字段；
- **停顿**：`pause_after_ms` 由 speaker 线程 sleep，不阻塞主链；
- **打断**：停演 / 切幕 / 重来 → `ctx.tts().interrupt()` 清队列；
- **不念你的话**：演员不得复述你的原话（ASR 可能是错的），只能回应意思。

---

## 7. 守卫

| 问题 | 处理 |
|---|---|
| 同一句 ASR 重复到达 | 去重窗口 1.5s |
| 麦克风捡到喇叭里自己的声音 | TTS 忙 + 尾音 0.8s 内，文本像最近 3 句自己的台词 → 丢弃 |
| 一句话被 ASR 切成几段 | 间隔 < 400ms 或字数 < 6 的碎片不进演员，只更新上下文 |
| 你连着说、模型还没回 | Actor 单线程队列，深度 2，满了丢最旧 |
| 模型乱跳 | 工具内 clamp：`max_jump`、`lookahead`、`show_jump` 只认暗号或明确 reason |
| 一回合卡死 | 8s 超时 → 走保底（§8） |

---

## 8. 保真与保底

- `fidelity` **只管喵呜的台词**（`speak`）：
  - `exact`：相似度 < 0.85 → 丢弃模型输出，直接念原文；
  - `natural`（默认）：照稿说，允许语气词，记相似度备查；
  - `improv`：稿子是骨架，允许展开（不适合正式演出）。
- `fallback`：LLM 超时 / 不可用 / 两轮无产出 → 直接 verbatim 念 `speak.text`，计一次 fallback，节目不中断。
- `advance_bias`：`steady`（默认，宁可等） / `eager`（宁可进，错了用「重来一遍」回退）。

## 9. 触发与生命周期（v2 缺的部分）

### 9.1 一个前提：硬触发时主链不说话

`pre_route_plan` 先看 `match_keyword`，命中就直接 return，**主链那一轮不调 LLM、不生成回复**。
所以：**凡是硬触发的动作，必须由插件自己开口**，否则你会觉得喵呜无视你。

由此定死三条规矩：

1. **控制动作**（准备/整理/排练/开演/停演）→ 用 `trigger_words` 硬触发 → **Actor 事件回合**负责说话；
2. **普通聊天** → 主链正常回（prep 期间 `route_text` 旁听、返回 False）；
3. **演出/排练期间** → `route_text` 全接管（返回 True），一切输入进 Actor，主链彻底闭嘴。

> 嘴只有一个来源，不会出现"主链说一句、插件又念一句"的双声。

### 9.2 动作与触发词

| 动作 | 硬触发词（`trigger_words`） | 只在 | 前置条件 | 说什么 |
|---|---|---|---|---|
| `prep` | 准备节目 / 准备一期 / 开个新节目 / 新节目 / 做一期节目 | 空闲 | 无 | Actor 开场："想做什么样的节目？" |
| `draft` | 整理成稿 / 写成稿 / 存稿 / 出稿 / 整理一下稿 | 空闲 / prep | 有 prep 记录 | 先跑 Scribe 写文件，再说"整理好了，四幕十八拍" |
| `rehearse` | 排练一遍 / 排练一下 / 走一遍稿 / 对一遍稿 | 空闲 | 有合法稿子 | "好，从头走一遍" |
| `perform` | 开始演出 / 正式开始 / 开演 / 开始节目 | 空闲 | 有合法稿子 | 倒数 3 秒 → 第一拍 |
| `stop` | 结束演出 / 收工 / 演完了 | rehearsal/perform | 会话中 | "收工，我整理一下" |
| `status` | 演到哪了 / 还有多久 | 会话中 | — | 口述进度（排练/筹备可用；演出建议少用） |

动作解析：工具只有一个 `podcast(action=..., request=...)`。
LLM 意图路径直接给 `action`；硬触发路径只有 `request`，按 `ACTION_WORDS` **最长匹配**回推动作（触发词本来就是确定的短词，不会错）。

**为什么开演必须硬触发**：走 LLM 意图路径时，主链会先流式说一句"好呀，那我们开始吧"，
插件再念开场 → 双声。硬触发把主链掐在前面，才不会撞。

### 9.3 前置自检（任何 start 之前，失败就由 Actor 说出来）

| 检查 | 失败时 |
|---|---|
| `toolbox.fast_reply_direct_tool: true` | 演不了（收不到你的话），直接说明并让去 `config.yml` 打开 |
| 未静默（`SilenceState().muted`） | 静默下 `msg_deal` 就把输入吞了 → 说明并拒绝 |
| 未在唱歌 | 拒绝，提示先结束唱歌 |
| 稿子编译通过（`show.json` 有效、无校验错误） | 指出行号，拒绝开演 |
| 没有别的 podcast 会话在跑 | 已在演出 → 不重启（返回 `already_running`，不出声） |
| Actor 端口可用（有 key / client） | 降级：仍可 verbatim 演，但先说清"今天我只能照着念" |

### 9.4 状态机

```
idle ──prep──▶ prep ──draft──▶ prep(有稿) ──perform──▶ perform
  │              └──────────────rehearse──▶ rehearsal
  ├──perform（用 default_show / 最近一场）
  └──rehearse
perform ⇄ paused
perform/rehearsal ──stop / 异常 / teardown──▶ idle（exit 状态位 + 归档 + 报告）
```

- `prep` 期间**不占状态位**（主链照常工作），`route_text` 旁听记录；
- `rehearsal` / `perform` 进入时 `state().enter()`：关主动回复、弹幕、礼物、提醒、其它工具箱；
- 退出走 `finally`，异常也保证 `exit()`（不留残留占用）。

### 9.5 筹备（prep）怎么开始、怎么结束

1. 你说「我们准备个节目」→ 硬触发 `podcast(action=prep)`：
   - 没有节目 → 新建 `show_id`（slug+日期），写 `show.md` 骨架（标题 + 空幕）；
   - 有 `default_show` → 问一句"接着上次那期，还是开新的？"（Actor 事件回合）；
   - 进 `prep`，**不占状态位**。
2. 筹备期你和喵呜正常聊（主链负责说话），插件只做两件事：
   - 每句你的话写进 `prep_log.jsonl`（文本 + 时间）；
   - 喵呜的话不抓，整理时从 `ShortMemory` 读最近的对话。
3. 你说「整理成稿」→ 硬触发 `draft`：
   - 先跑 **Scribe**（文档工具循环，不发声）→ 写/改 `show.md` → 编译校验；
   - 再用 **Actor 事件回合**说一句"整理好了，四幕十八拍，第一幕是……"；
   - 校验失败 → Actor 说"第三幕第 7 行没写角色，我指给你听"（带行号）。
4. 改稿：`第三幕砍一半` / `这段加两句` → LLM 意图路径（不用硬触发，主链正常回），
   Scribe 定向改 + 版本号 +1。
5. 结束筹备：直接说「开始演出」/「排练一遍」，或离开（`prep` 不占状态位，没有"退出"负担）。

### 9.6 开演（perform）怎么开始

1. 硬触发 `perform` → 前置自检（§9.3）：
   - 没有稿子 → Actor："还没稿子呢，要先准备一期吗？"（停在 idle）
   - 稿子校验失败 → Actor 报行号（停在 idle）
2. 通过 → 依次：
   - `state().enter()`（占位，让别的模块闭嘴）；
   - 起 speaker / actor / 记 `run_id`；
   - **倒数 3 秒**（可配 `countdown=0` 关闭）：TTS 念"三、二、一"，或 Actor 说一句开场语；
   - 定位到第一拍：`auto` 的喵呜拍直接念；`我` 拍则等你开口。
3. 演出中：`route_text` 全接管，暗号优先（§9.7）。
4. 结束：说「结束演出」/「收工」（暗号）→ 停 speaker → `interrupt()` → `exit()` → 写 `report.md` → 退 idlex。

### 9.7 会话暗号（只在 rehearsal/perform 生效，短句精确匹配）

| 你说 | 动作 |
|---|---|
| 停一下 / 暂停 | 暂停（TTS 清空，保持状态位） |
| 继续 / 接着来 | 恢复 |
| 提示我 / 我忘了 | 提词（`hint_mode`: 说出下一句 / 只写 live.json / 角色口吻催） |
| 上一句 / 重来一遍 | 回退一拍重说 |
| 下一句 / 跳过这句 | 前进一拍 |
| 下一个话题 / 跳到下一幕 | 切幕 |
| 结束演出 / 收工 | 收尾归档 |

暗号要求 ≤8 字 + 白名单命中，避免把正常台词当命令；命中后不进 Actor。

### 9.8 边界情况

| 情况 | 行为 |
|---|---|
| 演出中又说「准备节目」 | 暗号没命中 → 进 Actor 当台词；想换节目先说「暂停」再「收工」 |
| 重复说「开始演出」 | 已在运行 → 直接忽略（不出声、不重启） |
| 静默状态开演 | 拒绝并说明（静默下插件收不到输入） |
| 开演时主链正在生成别的回复 | 等它说完再开（检查 `ctx.tts().is_busy()`，最多等 5s） |
| 稿子中途被改 | 演出用的 `show.json` 冻结；改稿只影响下一次开演 |
| 插件被卸载（`teardown`） | 停线程 → `interrupt()` → `exit()` → 归档（尽力） |

## 10. 文档

目录（按 meowid 隔离）：

```
character/plugin_data/podcast/<uid>/
├── shows/<show_id>/{show.md, show.json, meta.json, history/}
├── runs/<run_id>/{run.jsonl, report.md}
└── recent.json
```

`show.md` 语法（沿用 v1，语义按 §3 改了）：

```markdown
---
title: 深夜猫话 · 第 12 期
target: 30m
codewords:
  下一个话题: next_scene
  该收尾了: end
---
# 第二幕 · 正文
@scene 03:00-18:00

我：讲加班那段（要点：加班到十一点 → 地铁没了 → 走回去）
  锚词: 加班,十一点,地铁,走回去

喵呜（好奇）：你那天到底几点才到家？

我：十二点多，地铁都没了。
  锚词: 十二点,地铁

喵呜（心疼）：这么晚……那你后来怎么回去的？
```

编译校验：角色可归属、`speak` 非空、`@scene` 递增、相邻 `intent` 不能重复（防两拍抢同一段）。
编译产物只读；md 改动（mtime/版本）→ 重编译。

## 14. 分期与验收

**P0 能演一场**：解析编译 + 5 个工具 + 两轮演员循环 + TTS 分段 + 守卫 + 硬触发开演/停演。
验收：10 拍小节目，**故意把稿子念错几个字**也能接上；同段说三句碎片只推进一次；
单回合延迟 P50 ≤ 3s；无双声；模型挂掉能 verbatim 演完。

**P1 排练与复盘**：run.jsonl/report.md、排练提醒、`fidelity`、暗号、`advance_bias`。

**P2 筹备**：Scribe + 文档工具 + prep 旁听记录 + "整理成稿"事件回合。

**P3 提词面板**：独立进程 `console/server.py`（仿 `pig_game/tool/server.py`，只监听 127.0.0.1），
读 `live.json` 显示当前拍 / 喵呜下一句 / 待讲要点 / 进度条；按钮写 `control.json`，插件轮询消费。

## 15. 风险

1. **两轮调用延迟** ~1.5~2.8s：对话里是自然停顿，但要实测；缓解=第二轮短、`tools=None`。
2. **provider 不支持 `required`**（本地小模型）：退回 `auto`+催一次 → 再退"一次调用出 JSON"（伪 FC）→ 最后 verbatim。
3. **模型判错位置**：clamp + `allowed` 回显 + 暗号回退（「上一句」）；报告逐拍可查。
4. **ASR 太差**（长句丢一半）：`advance_bias=steady` 会等成空场 → 用「下一句」暗号或面板手动推进兜底。
5. **回声自激**：三重屏蔽；压不住就把接受窗口缩到"你说话后 3 秒"。
6. **硬触发词误命中**（日常聊天说了"准备节目"）：可接受（意图明确），且 `trigger.enabled` 可关。
