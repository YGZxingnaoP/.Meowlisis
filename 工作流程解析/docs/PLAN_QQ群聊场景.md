# QQ 群聊 @ 工具

## 工具

```
group_at(member)
member: 群名片 / 昵称（可近似）/ QQ 号
```

只指定人，不写内容。**这是可选的**：默认不加 @，绝大多数回复直接说就行；只有确实要单独对某个成员说话、需要他看到时才调用。调用后这条回复的第一段以 @他 的形式发出：

| 模型行为 | 实际发送 |
|---|---|
| 调 `group_at(熙欧_筱狐)` + 正文「你怎么勾引主人」 | 一条 `@熙欧_筱狐 你怎么勾引主人` |
| 调工具 + 正文两段 | 第一段带 @，第二段普通 |
| 只调工具、没正文 | 只发 `@熙欧_筱狐` |
| 名字解析不到 | 忽略 @，正文照常发 |

## 发送路径

`reply()` 拿到 `(正文, 目标)` → 第一段交给 `TBGroupAt.send()` 发出（at 段 + 文本）→ 剩余段仍走原来的 `on_segment` 回调。

**`on_segment` 保持单参数**，外部调用方（海龟汤、docwriter 插件）不用改。

## 为什么不会有重复

@ 不是独立消息，而是跟第一段正文绑在一起发。整条回复只有一次"第一次发送"的机会，不存在工具发一遍、正文再发一遍。

## 改动

| 文件 | 改动 |
|---|---|
| `groupchat/group_at.py` | 工具只收 `member`；`resolve()` 找成员，`send()` 发 at |
| `llm/napcat_group_llm.py` | `_generate_with_tools` 返回 `(正文, 目标)`；`reply()` 用目标发第一段 |
| `toolbox/qq_response.py` | 回调签名不变（无改动） |

## 跨链路检查

| 链路 | 状态 |
|---|---|
| 私聊 `TBNapCatLLM.reply` | 不受影响（`_drop_current_from_history` 有单测覆盖） |
| 群 @ / 关键词 / 主动强制 | 正常，第一段带 @ |
| 群主动插话 `decide()` | 不传 `group_at`，行为同以前 |
| 海龟汤 `_host_reply_qq` | 回调单参数，正常；若模型调工具，@ 由 `reply()` 直接发出 |
| docwriter 插件 `_complete_qq` | 同上 |
| 幻梦评价 `_reply_bot_reply` | 不传回调，`reply()` 不发消息，由调用方发纯文本 |
| 视觉 `_reply_group_image` | 不经过 `reply()`，纯文本 |
| 插件 / 意图分析 / 破甲 / 改图 | 用不带人名的纯文本，不受前缀影响 |

已修的两个跨链路问题：

1. **`on_segment` 回调参数**：中途改成 `(seg, at)` 会打断海龟汤和 docwriter 的单参数回调（TypeError）。现在回调保持单参数，@ 由 `reply()` 自己发第一段。
2. **人名前缀污染其他链路**：`【名字】:` 只喂给 LLM；插件、意图分析、破甲、改图判定改用纯文本，避免像「接受」这种精确匹配的指令失配。

## 验证

```
工具+正文     → at 一条（含正文）
工具+两段正文  → at 一条 + 普通一条
工具+无正文    → 只发 at
工具-简称/QQ   → 命中同一成员
工具-找不到    → 纯文本，不 @
无工具        → 普通回复
无回调路径     → 不发消息，无重复
chat 崩/空    → 回退流式，普通回复
```
