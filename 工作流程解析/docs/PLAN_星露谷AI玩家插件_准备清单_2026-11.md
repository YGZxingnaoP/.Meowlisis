# 方案：星露谷 AI 玩家插件 —— 准备清单与首期架构

> 只做准备清单 / 方案，未改代码。日期 2026-11-06。
> 目标：在 `plugins/` 里做一个能真正玩《星露谷物语》的插件——全操作、听指挥、写日记、和 QQ 群聊天、和其它 AI 角色联机。

---

## 0. 先看三个硬结论

1. **星露谷没有合法免费版。** 免费只有两条路：Game Pass 试用（首月约 ¥10），或退到免费替代品先练手。盗版不给指引，而且 SMAPI 生态在盗版上会卡版本、日志、社区支持——省下的 ¥48 不值。
2. **"实现所有操作"必须走 SMAPI mod 直接调游戏 API，不要做截图 + 模拟键鼠。** SMAPI 官方给了 `Helper.Input.Press()`（等价真人按键）、全量状态读取、Harmony patch。截图方案在 60fps、UI 缩放、遮挡、室内多地图面前会立刻崩。
3. **多 AI 角色最便宜的做法：一台机器分屏 4 人 = 一份游戏。** PC 1.6 联机上限 8 人（7 个木屋）；分屏最多 4 人，**键盘永远属于 1P，2/3/4 号位要各接一个手柄**——实体手柄或 ViGEmBus 虚拟手柄都行。远程联机则每人一份游戏。

## 2. 三条路线，先选一条

| 路线 | 需要什么 | 真实度 | 建议 |
|---|---|---|---|
| **A. 正版 + SMAPI 桥接** | 一份游戏 + C# 基础 | 100% | 目标形态，5 个诉求全部能落地 |
| **B. 免费替代品先练手** | 0 元 | 0%（不是星露谷） | 只用来先跑通「AI 决策→动作→日记→QQ」的骨架，后面换皮 |
| **C. 纯文本模拟** | 0 元 | 假 | 已有 `pig_game` 先例，但永远不是「玩星露谷」 |

路线 B 的免费候选（都可脚本化、可联机、可无头跑）：

- **Luanti (Minetest)**：Lua mod、独立服务器、多 bot 同服——**最适合先练「多 AI 同一个世界」**
- **Dwarf Fortress（免费版）+ DFHack**：Lua 脚本、有农场、ASCII
- **自建 2D 农场 sim（Godot / Pygame）**：最自由，但要先写游戏

结论：B 省下的钱不值当，**直接 A**。真想 0 元起步，先花两天在 Luanti 上把「多 AI 同服 + 指令 + 日记」跑通，再买游戏换皮。

## 3. 架构（A 路线）

```
[SMAPI Mod: StardewAgent]   C#, net6.0
   ├─ Snapshot  只读快照，每 2s 一次
   │    时间/季节/天气/位置/体力/金钱/背包/任务/农场地图/NPC 好感/作物状态
   ├─ Executor  原子动作执行器
   │    走位 / 用工具 / 种 / 浇 / 收 / 砍 / 挖 / 钓 / 买卖 / 送礼 / 对话 / 睡觉 / 开箱
   ├─ EventLog  事件流：做了什么、赚了多少、受伤、节日、卡住
   └─ Bridge    本地 HTTP + WS，只绑 127.0.0.1:8756，不暴露公网

[Python 插件: plugins/stardew_agent/]
   ├─ bridge.py     跟 mod 通信（订阅快照 / 下发命令 / 超时重试）
   ├─ skills/       确定性技能库：浇完这片地、钓到 5 条、清空背包
   ├─ planner.py    LLM 高层规划：今天干什么 / 目标拆解 / 卡住了怎么换
   ├─ memory.py     日事件流 → 长期记忆
   ├─ diary.py      睡前写日记 → markdown + 截图 → 群 / 空间
   ├─ qq.py         群指令解析 + 播报（命中前缀才接管）
   └─ npc_chat.py   和村民 / 群友对话（走现有 LLM 管道 + 角色提示词）
```

**唯一不能违反的分层原则：**

> LLM 只做「每隔几十秒到几分钟一次」的高层决策；每一步走位、每一次挥锄头，由确定性代码完成。

每 tick 调一次 LLM 的方案一定烧钱烧到崩，而且响应不过来。参考 Minecraft 的 Voyager 思路：**技能库 + 目标重规划**，而不是「用语言模型操控像素」。

### 3.1 mod 侧协议草案

```
GET  /state              → 快照 JSON
GET  /events?since=<id>  → 事件流
POST /command            → {"op":"move_to","x":12,"y":8,"timeout_ms":8000}
POST /pause | /resume    → 暂停 / 继续（调试和切场景用）
```

快照草案（给 planner 看的那一份，字段要先瘦身，别把整张地图塞进去）：

```json
{
  "game": {"day": 12, "season": "spring", "year": 1, "time": 930, "weather": "rain"},
  "player": {"name": "喵呜", "tile": [12, 8], "location": "Farm", "energy": 210,
             "money": 1240, "inventory": [{"id": "18", "name": "土豆", "count": 5}]},
  "farm": {"watered": 12, "unwatered": 8, "ready": 3, "empty_tiles": 40},
  "quests": ["把 5 个土豆交给 Pierre"],
  "npc": [{"name": "Abigail", "hearts": 2, "location": "SeedShop"}]
}
```

### 3.2 群指令草案

| 群里说 | 效果 |
|---|---|
| `星露谷 去钓鱼` | 目标入队，下一轮规划优先执行 |
| `星露谷 今天种土豆` | 改当日计划 |
| `星露谷 状态` | 回一条当前状态卡（时间/钱/体力/在干什么） |
| `星露谷 日记` | 发最近一篇日记 |
| `星露谷 停` | 立刻回到待机 |

沿用 `pig_game` 的原则：**没命中前缀 → 完全不接管，零 LLM 负担**；命中才走 `route_qq`。

## 4. 五个诉求逐条怎么落地

| 诉求 | 实现方式 | 难点 | 首期能到哪 |
|---|---|---|---|
| **实现所有操作** | Executor 覆盖约 40 个原子动作；走位用 A*（读地图障碍层）+ 碰撞，不靠像素 | 钓鱼小游戏、战斗、节日、剧情 cutscene 会打断控制 | 种/浇/收/砍/挖/钓/买/卖/送礼/睡觉，够过完一年 |
| **听从用户建议** | 群消息 / 语音 → 解析成「目标」进 planner 优先级队列；另建「建议簿」，群友零散建议存下来供规划参考 | 指令冲突仲裁、恶意指令（让别人家的 AI 去干傻事） | 用户指令 > 自己规划，且可随时撤销 |
| **写日记** | 每晚睡觉事件触发：当天事件流 + 数值变化 → LLM 写第一人称日记 → 按游戏日期存 markdown，配游戏内截图 | 别写成流水账——要把事件流压缩成「今天的心情」 | 每天一篇，可发群 / 发空间 |
| **和 QQ 群正常对话** | 复用现有 NapCat 链路；用 `qq_knowledge` 注入「农场当前状态」，让回复有上下文（"我在钓鱼，今天赚了 1200g"） | 别把每条群消息都过一遍 LLM | 状态卡 + 自然插入对话 |
| **和其它 AI 角色联机** | 同机分屏 4 人：每个屏幕 = 一个 Farmer，SMAPI 每 tick 跑 4 次（`PerScreen`），mod 按 `ScreenId` 驱动各自农民；每个角色一份人格 + 独立决策线程 | 分屏调试痛（4 个屏幕共用一份控制台）、虚拟手柄、角色间对话不能互相刷屏 | 先 2 个 AI 角色同屏，再扩到 4 |

> 如果以后要和**真人**一起玩：每人一份游戏 + 远程 Co-op（1.6 支持 8 人）。那时 AI 角色跟着主机走，注意别在别人主机上自动化——容易被当挂 kick。

## 5. 分阶段里程碑

| 阶段 | 内容 | 预估 |
|---|---|---|
| **P0** | mod 起 HTTP，Python 侧拿到快照，日志能看到时间/位置/体力 | 1–2 天 |
| **P1** | 单动作：走到 (x,y)、用工具、浇水 | 3–5 天 |
| **P2** | 农场循环：种/收/浇/卖/睡觉，**不接 LLM 也能自动过完一天** | 1–2 周 |
| **P3** | LLM 规划：目标拆解 + 失败重规划 + 每天调用次数上限 | 3–5 天 |
| **P4** | QQ 接入：群指令、状态播报、状态注入 | 2–3 天 |
| **P5** | 日记 | 1–2 天 |
| **P6** | 分屏多角色：虚拟手柄、PerScreen 驱动、角色间对话 | 1–2 周 |

P2 是关键分水岭：**不接 LLM 也能自动过一天**，说明动作层是可靠的；否则后面所有智能都在给不稳定的手打补丁。

## 6. 坑与风险（提前认领）

- **版本跟进**：SMAPI 每次游戏更新（1.6.x）都会让 mod 失效。`MinimumApiVersion` 要写，构建脚本要能一键重编。
- **时间尺度**：游戏内 1 天 ≈ 14 分钟真实时间。LLM 一次决策若 10 秒，一天只能做几十个决定，且会被「时间流逝」惩罚。对策：TimeSpeed 调速 mod（只有主机装才生效）+ 关键决策前 `pause`。
- **寻路**：星露谷没有官方寻路 API，要自己读 map 的障碍层；室内、矿洞、四季地图、下雨天的碰撞都要测。
- **分屏调试**：4 个屏幕共用一份 SMAPI 控制台，日志要按 `ScreenId` 打标签，否则没法定位。
- **存档安全**：SMAPI 自带 SaveBackup，但每次大改动作逻辑前还是手动备份 `%AppData%\StardewValley\Saves`。
- **成本**：每天玩 4 小时、5 分钟一次规划 ≈ 48 次/天，再加对话；DeepSeek 级别完全可接受。**不要每 tick 调**。
- **插件侧规范**：数据一律 `ctx.data_dir()`（不要写插件目录），配置走 `schema.py`，群指令前缀可配，未命中前缀零打扰。
- **别做的事**：盗版、别人主机上的自动挂机、把 mod 的 HTTP 端口暴露到公网。

1. **买游戏 + 装 SMAPI**：Steam/GOG 买，跑 SMAPI 安装器，进一次游戏确认能进存档。
2. **装 .NET 6 SDK + VS2022（.NET 桌面开发）**：按官方模板建一个空 mod，编译成功、游戏里能看到日志。
3. **定形态**：多 AI 走「同机分屏」还是「远程多份」；以及要不要我先把 **mod 骨架 + `plugins/stardew_agent/` 骨架**搭出来（能编译、能起 HTTP、能给群发状态卡，但不含具体动作）。

## 附：目录规划建议

```
plugins/stardew_agent/          Python 插件（插件加载器只认这里的 plugin.py）
├── plugin.py                   Plugin + TriggerTool + route_qq
├── schema.py                   GUI 配置（游戏路径、端口、群开关、人格）
├── bridge.py / planner.py / diary.py / qq.py / memory.py
├── skills/                     确定性技能
└── game_mod/                   C# mod 源码（.csproj + ModEntry.cs）
                                ↳ 构建产物拷到 <游戏>/Mods/StardewAgent/
```

C# 源码放插件目录内是为了「一个插件一份交付物」；插件加载器只 import `plugin.py`，不会碰 `game_mod/`。
