# 心理状态机 × 导演模块（主链路）设计方案

> 版本：2026-10-29
> 范围：**只做电脑端主链路**（语音 / API / 手机语音）。QQ 本期不动，见第 9 节。
> 性质：只做分析与方案，**本文不含任何已实施改动**。
> 结论先行：新增 `func/llm_active/director/` 一套「导演核心（规划 + 表演 + 监工）」，在
> `func/pipeline` 新增两条桥接（状态/事件、入口接管），心理状态机只负责把导演状态渲染成
> 「当前对话走向」块并插进 system_prompt；主链路在导演激活期间把用户回合让给导演回复引擎
> （llm_active 内**复制**一份主链路回复逻辑，不 import 主链路代码）。

## 1. 现状事实（读代码得到的硬结论，方案的地基）

### 1.1 主链路（`func/llm/llm_core.py`）

  1. 取队列、身份校验（171-179）；

  6. `tb.attach_tool_hint`（243-244）；
  7. `message_builder.build_messages`（247）；
  8. 用户短期记忆 `add_user_message`（258）；
  9. `Output(config, llmData, source)`（261）；
  10. δ-mem 上下文 `memory_options.set_current_uid/as_options`（273-275）；
  11. 流式 + 工具累积（281-303），空正文但有工具调用时补回执（305-308）；
  12. `finalize`（317）、清线程上下文（322）、工具分发（325-327）；
  13. 情绪更新线程（330-331）；
  14. δ-mem 写入 `DmemBridge().remember`（341-348）；
  15. 助手侧记忆（350-372）；

- 流式清洗 `func/llm/output.py`：逐字符剥离 think/【】/（），`NarrationCleaner` 水词清洗，按 `split_chars`/`split_limit` 切段，经 `LLMTtsBridge.send_to_answer_queue` 推 `LLmState.AnswerList`。

- 计时桥 `func/pipeline/llm_timer.py`：**单回调**（`register` 会覆盖），`notify_ai_reply()` 无参数。

### 1.2 主动回复（`func/llm_active/`）

- `AutoActiveCore`（api.py 84 行处实例化；main() 里 1 秒轮询 `check_active`）：
  - `_on_user_message`（76-79）重置计时 + `_n=0`；`_on_ai_reply`（81-83）重置计时；
  - `check_active`（93-100）：插件让位 + `_running` + `timer.is_due()` → `_trigger`；
  - `_trigger`（119-129）：`_n+=1`；`_n<=n` 走 `inherit.run()`，失败再 `origin.run()`；否则 `origin.run()`；结束 `timer.reset()`。
- `AutoTimer`（timer.py 19-43）：`reset()` 抽 `cold_time*random(0.8,1.2)`，pause/resume 顺延。**本期不改**。
- `inherit`（inherit_core.py 34-77）：读 `.temp/current_topic.json` + 全量短记忆，`auto_reply` 工具（continue_topic + reply_content）→ `Output.remove_analysis` → 整段 TTS → 只写 assistant（type=`llm_active_response`）+ 长期记忆。
- `origin`（origin_core.py 37-143）：`AutoRandomTopic.pick()`（random_topic.py 19-41，话题 + `web_browse` 缓存视频统一随机池，**视频是概率出现的**）→ 话题分支拼档案/摘要 → 流式 `chat_stream(options={"enable_thinking": True})` + `Output(enable_narration=False)`；视频分支用视频信息当「由头」；消费后 `AutoBrowseStore.move_to_collect` 移到收藏。
- 端口 `func/llm_active/port/*`：`chat`（非流式，支持 tools/tool_choice/options）与 `chat_stream`（流式，支持 tools/tool_choice/options）；`max_tokens = min(base*2, 2048)`；**思考参数默认取 `LLMConfig`**（当前 `llm.deepseek.enable_thinking: true`）。
  - ⚠ 已知隐患（不是本次引入）：DeepSeek 在 thinking 开启时拒绝强制工具调用；`inherit` 用 `chat(tools, tool_choice=强制)` 且不传 options，若配置开着 thinking，这次调用会 400 → 直接转 origin。导演的规划/判官/折叠工具调用必须显式 `options={"enable_thinking": False}`。

### 1.6 QQ 现状（本期不动的依据）

- 私聊：`receive_qq`（qq_response.py 40-152）只在收到消息时回复，**没有任何主动触发**。
- 群聊「自己开口」只有两条路，且都不是计时：
  - ① 主动插话：普通消息累计到 `group_reply_base` → `TBNapCatActive.on_message` 返回 `decide`（napcat_active.py 26-78）→ `napcat_group_llm.decide` 输出 pass/回复（qq_response.py 538-609）；
  - ② 续聊：@/关键词回复后 `TBGroupFollowup.arm`，后续普通消息由 `TBNapcatFollowupJudge` 判 continue/pass（qq_response.py 611-672）。
- 群聊提示词在 `get_napcat_group_prompt` 内注入 QQ 心理块（426-428）。
- 结论：QQ 的「主动」是**消息驱动**的插话/续聊，和主链路的「空闲计时→主动回复」不是同一套状态机。本期不碰。

## 2. 总体设计（一页纸）

```
                          ┌─────────────────────────────┐
   主链路一轮回复结束 ───▶ │ 无聊判官 judge（异步，LLM） │──bored──▶ AutoActiveCore.trigger_now()
   (notify_ai_reply)      └─────────────────────────────┘                │（跳过 cold_time）
                                                                          ▼
   空闲计时到期 ───────────────────────────────────────────────▶ ┌────────────────────┐
   (AutoActiveCore._trigger)                                      │ DirectorCore        │
                                                                  │  ① 规划 planner     │
                                                                  │  ② 表演 responder   │
                                                                  │  ③ 折叠监工 step    │
                                                                  └─────────┬──────────┘
                                                                            │ 写 .temp/latest_director.json
                                                                            ▼
                                                       ┌──────────────────────────────┐
   导演激活后的用户回合 ──▶ api.py 入口桥 ────────────▶ │ msg_director → responder      │
   （llm_active 复制的主链路回复逻辑）                  └──────────────────────────────┘
                                                                            │
   心理状态机渲染 ◀──最新导演状态───────── SystemPromptBridge._psyche_block(with_director=True)
   → 「# 我心里装着的 …」+「# 当前对话走向（必须照做）… 代码块」
```

四条主线：

1. **进入**：每轮主链路回复结束后，导演核心异步判「主人是不是无聊 / 话题是不是断了」；是 → 跳过 cold_time 立刻走一次主动回复，并直接进入导演（不再让规划器重复判启动）。空闲计时到期时，由规划器自己判「要不要开导演」，不开始就完全走原来的 inherit/origin。
2. **规划**：`director_plan` 工具输出结构化 todolist（步数不限、只写行为/思想，不写台词），素材来自现成概率池（话题 / `web_browse` 视频）。
3. **表演**：导演激活期间，用户回合由 `msg_director` 桥接管，交给 llm_active 内**复制**的主链路回复引擎；每回合只推进当前这一步，同时用同一次生成里的折叠工具 `director_step` 交回「完成 / 下一步 / 要不要 clear」。
4. **呈现**：心理状态机把导演状态渲染成「当前对话走向」代码块，插在「我心里装着的」下方；块里明确 `[x] 已完成 / [>] 当前 / [ ] 之后` + 硬规矩。

## 3. 设计细节

### 3.1 状态与桥接

**状态文件**：`.temp/latest_director.json`（运行时缓存，与 `latest_psyche.json` 同级）。
**桥接**：新建 `func/pipeline/llm_director.py::LLMDirectorBridge`（单例），只做三件事：

```python
# 读
get(scope="main") -> dict          # 不存在/损坏返回 {}
is_active(scope="main") -> bool
# 写
set_state(scope, state: dict)      # 内存 + 原子落盘（tmp + os.replace）
clear(scope, reason="")            # active=False、记 clear_reason、保留最近一次计划备查
# 事件（"主链路 ↔ 导演"的唯一通道）
register_host(is_busy, flush_history)   # 由 LLmCore.__init__ 注册（唯一跨模块注册点）
can_take_over() -> bool                 # active 且 !is_busy() 且 未被静默/插件禁用
subscribe_events(on_entered, on_cleared) # 导演核心订阅；进入/退出时让主链路 flush 短记忆
```

**为什么状态不放心理文件里**：`MeowPsycheCore._store` 每次整块覆盖 `latest_psyche.json`（`set_psyche` 直接 `json.dump(data)`），导演字段会被洗掉；而且心理生成是 5s 轮询、可能落后。分文件、各自拥有、心理只读，边界最干净，也正好满足「心理状态机只负责提示词整理插入」。

**scope**：`main` 现在用；`qq` 只预留键名，本期不写任何 QQ 逻辑。

### 3.2 进入导演的两条路径（都不许出现关键词）

#### 路径 A：无聊判官（每轮异步，主链路触发）

- 挂点：`LLMTimerBridge.notify_ai_reply()`（`_ai_response` 末尾 377-378 已经调用）。把桥接扩展成多播 + 带 `source`，导演核心订阅；判官只对 `source != "danmaku"` 且「最后一条 assistant 指纹变了」才跑（指纹逻辑照抄 psyche `_latest_reply`，避免 pre_route 提前 return 那种没有新回复的重复判）。
- 输入：`ShortMemory.load_by_type(("llm_fast_response",))` 最近 `judge_history_rounds` 轮（默认 8）+ 当前心理（`LLMPsycheBridge().get_psyche("main")`）。
- 输出：工具 `judge_bored` →
  `{"bored": bool, "no_topic": bool, "reason": "必须引用原话片段", "next": "我想干什么（起话题/逗他/问他/关心/不说）"}`

- 冷却：`cooldown_after_clear`（默认 600s）内不触发；导演已激活时不判；静默 / 插件禁用 / 唱歌中不判。
- 该调用用 llm_active 的端口 + `options={"enable_thinking": False}` + 小 `max_tokens`（临时抬/降 `llm.max_tokens` 后恢复，`followup_judge` 已有同款写法）。

`trigger_now` 的语义（`AutoActiveCore` 新增）：

```python
def trigger_now(self, reason="bored"):
    if not self._allow_active_reply():      # 插件状态总线
        return False
    if self._running:                        # 已有一次触发在跑
        return False
    self._running = True
    Thread(target=self._trigger_safe, kwargs={"reason": reason}).start()
    return True
```

`_trigger` 增加**第一个**分支（其余一行不改）：

```python
def _trigger(self, reason=None):

    ... 原有 inherit/origin（原样保留）
```

- **计时零改动**：`AutoTimer` 一字不改；`trigger_now` 只是在计时到期前**额外**调用同一条 `_trigger`，结尾照旧 `timer.reset()`。
- 判官不用任何词表；`reason` 必填且要求引用原话，等于强制「有证据才判无聊」。

#### 路径 B：空闲计时到期（`timer.is_due()`）

`on_idle_trigger(forced=False)`：

1. 规划器先判 `start`：不开始 → 返回 `False`，`_trigger` 继续走原 inherit → origin（**完全不变**）；

### 3.3 规划（planner）

新建 `func/llm_active/director/planner.py::DirectorPlanner`，一次 `plan(kind, uid=None, reason="")` 内部：

1. **素材**：`material.py` 调 `AutoRandomTopic().pick()`（原概率池：话题 vs 缓存视频），
   - 视频：取 `title/len/uploader/content/topic/tags`，保留原「由头不是任务」的说法；**只有在本次计划真的开始后才 `move_to_collect`**（失败不消费）；

   - 计划里只留 `{type,title,topic,tag,path,brief}`；`brief`（视频=标题｜内容摘要≤400字，回忆=话题（标签））会渲染进导演块的 `由头：…` 一行，供执行回合记住「这一场在聊什么」（不重复喂全文，避免照着念）；视频消费后计划里的 `path` 同步改成收藏路径。
2. **提示词**：`prompts/planner_prompt.txt`（角色卡走 `SystemPromptBridge().get_character_prompt()`，桥接）+ 当前心理 + 最近 6 轮 + 判官给的 `reason/next`（如果有）+ 素材。
3. **工具循环**（照 `CatValues.update_values._run_analysis` 的写法）：
   - 工具 = `LLMToolboxBridge().get_memory_schemas()`（新增方法，内部就是 `MeowFileAnalysis`）+ `director_plan`；
   - 最多 `planner_max_tool_rounds`（默认 12）轮；`options={"enable_thinking": False}` + `max_tokens=planner_max_tokens`（默认 1600）；
   - **导演核心自己持有一个 llm_active 端口实例**（判官/规划器/表演各用一个或共用导演自己的那一个，不与 `inherit/origin` 共享 `AutoActiveCore.llm`），所以临时改 `max_tokens` 只影响自己，不会和正在跑的 inherit/origin 串参数；

启动提示词要点（写死在 `planner_prompt.txt`，逐条对应需求）：

- 只在「主人明显没意思 / 聊天明确没话题 / 我正在问最近有什么好玩的视频」时 `start=true`；有明确话题、他在忙、刚聊起来 → `start=false`；
- 规划是**行为与思路**，不是台词：只写这一步要干什么、猜他会怎么接、他不接时怎么拉回来；
- 明确禁止冷笑话；
- 过程参考（不是固定模板）：引起注意 → 勾起兴趣 → 慢慢引导 → 设置转折 → 揭晓答案；
- 可用招法举例（明确写「不局限」）：让他猜东西、猜我下一句、关心他、考他记不记得、调戏他、卖关子、故意说错等他纠正；
- 可以调用文件工具去翻 `character/memory` 的记忆文本找素材；
- 视频只是由头：不要复述视频信息，不要出现「好的/我来分享」；

### 3.4 表演（responder）

新建 `func/llm_active/director/responder.py::DirectorResponder`，负责「导演激活期间所有开口」。四种回合：

| 回合 | 何时 | 用哪个系统提示词 | 记忆写法 |
|---|---|---|---|
| `start_bored` | 判官触发 | `get_system_prompt(uid, 主人最后一句, mark_first=False)`（主链路提示词，带用户档案/记忆；**uid 取 `MeowLLMLtMemBridge().last_uid`**——主链路每轮 `record_user_message` 会更新它；取不到就退回 `get_active_prompt`，否则后置词会拼出「你现在在和说话」） | 复制件 `MessageBuilder` 写 assistant 单条 + `record_ltmem_only` |

生成流程（**逐行对齐 `_ai_response`，见 4.4 的映射表**）：

1. 静默态 / 插件禁用 → 直接丢弃（不写「已回复」）；
2. `reply` 回合：`TBRulesBreak.check_and_store_msg`（破甲）→ 用户长期/档案 → `add_user_message`；
3. 系统提示词（含心理 + 导演块）→ 末尾再追加一段**本轮要求**（不是计划的一部分）：
   ```
   # 这一轮只做这些
   {reply: 他刚说的是「…」，只走当前这一步，别把后面说完}
   {idle: 他一直没说话，你有点失望（别抱怨、别卑微），换个钩子继续，别重讲}
   {rewrite: 这条路走不通了，按新的走向重新开口}
   ```
4. 工具：`[director_step] + (merge_on ? toolbox schemas : [])`；`tool_choice="auto"`；`options={"enable_thinking": False}`；`tool_choice` 不强制（要同时流式正文）；
5. 流式：复制件 `Output`（think/括号/水词/切段）→ 新增的 `LLMTtsBridge.send_chat_segment`（内部持有 `LLmState`，不 import llm 层状态）→ `AnswerList`（`source` 透传，手机/语音来源照旧推手机）；
6. 收尾：`finalize` → **先** `DirectorCore.apply_step(payload)`（先更新状态，供本轮后续与下一轮用）→ 再分发非 `director_step` 的工具调用（`LLMToolboxBridge.handle_tool_calls`）；
7. 空正文兜底：
   - 只调了 `director_step`、没正文 → **去掉全部工具重生成一次**（提示「只说话，别调工具」）；成功则用这次正文，且计划用第一次的 step 结果；
   - 仍为空 → 记 warning，不写「已回复」；
8. 记忆：`add_assistant_message` + 长期记忆（`reply` 用 `record_ai_message`，开场/失望用 `record_ltmem_only`）+ δ-mem（仅 `reply` 且有正式 uid）；
9. `LLMTimerBridge().notify_user_message()`（`reply` 回合）/ `notify_ai_reply(source="llm")`（所有回合，结束）；
10. 情绪：复制件 `EmotionController`（llm_active 端口，异步线程），写 `latest_emotion.json` + `LLMEmotionBridge`；
11. 并发：一个 worker 线程 + FIFO 队列（用户回合入队，不阻塞 api 线程）；空闲回合在触发线程里同步跑；两者共用一把锁。

### 3.6 失望循环、重写、退出

`DirectorCore.on_idle_trigger(forced=False)`（导演已激活时）：

```
1. 若「上次导演开口后收到过用户消息」→ silent_rounds = 0；否则 silent_rounds += 1
   （正常情况下计时到期本身就意味着这段时间没有用户消息；标志位只做防御）
2. silent_rounds < silent_rounds_limit（默认 3）
      → responder.speak("idle_disappointed")：表现出失望，只调/换当前这一步的做法（不重写计划）
3. silent_rounds >= 3
      → planner.plan(kind="rewrite")：重新挑素材（原概率池，可能换到视频）、整体换计划，
        写状态、reset silent_rounds → responder.speak("rewrite")
4. 任何一次用户回合（reply）→ silent_rounds = 0
```

- 计划**不设过期时间**、步数**不设上限**；只有 clear 或 3 次失望会结束/重写（满足需求 8/13）。
- clear 判定（全部由折叠工具给，代码里零词表）：
  - `director_step.clear=true`：`clear_reason ∈ {全部完成, 主人说不要打扰, 主人不想听了, 主人有明确话题, 没意思了}`；
  - 本地确定性兜底：所有 step 状态都 `done` → 自动 `clear("全部完成")`（防止模型忘了 clear 卡死）；
  - **不**做「N 分钟后自动结束」——需求明确不要时长限制。
- clear 动作：`LLMDirectorBridge().clear()` → 发 `on_cleared` 事件 → 主链路 flush 短记忆（顺序对齐）→ 下一次用户回合走 `llm`。
- 用户「不想听/别烦我」这类**不从词表判**：写在导演块和 `director_step.clear_reason` 的说明里，由模型判。

## 6. 时序

### 6.1 判官触发（主链路一轮之后）

```
LLmCore._ai_response 末 → notify_ai_reply(source) → LLMTimerBridge 多播
  → DirectorJudge.on_turn()（守护线程）
      · 指纹没变 / 导演已激活 / 冷却中 / 静默 / 插件禁用 → 直接返回
      · 取最近 N 轮 + 心理 → judge_bored（thinking off, max_tokens 小）
      · bored|no_topic 且 reason 非空 → AutoActiveCore.trigger_now("bored")
          → _trigger(reason="bored") → DirectorCore.on_idle_trigger(forced=True)
              → planner.plan(kind="start_bored") → 写状态 → on_entered(flush 主链路历史)
              → responder.speak("start_bored")（主链路提示词 + 导演块 + 本轮要求）
```

### 6.2 空闲触发（导演未激活）

```
AutoTimer 到期 → check_active → _trigger()
  → DirectorCore.on_idle_trigger(forced=False)
      → planner.plan(kind="start_idle")（内含 start 判断）
          start=false → return False → 原 inherit → 原 origin（一行未改）
          start=true  → 写状态 → responder.speak("start_idle")（active 提示词 + 导演块）
```

### 6.3 导演激活期间的用户回合

```
api.py /chat（或 /msg、sensevoice_callback）
  → excuse / singer / catpaws / turtle（原优先级，照旧）
  → MsgDirectorBridge.send_to_director(text, meowid, source)
      active && can_take_over && 允许 → enqueue → return True（api 立刻返回）
  → 数据库关键词（保留）；工具二通道（跳过）
DirectorResponder.worker
  → notify_user_message() → 破甲 → 用户长期/档案 → add_user_message
  → get_system_prompt（含导演块）+ 本轮要求 → build_messages
  → chat_stream(tools=[director_step]+toolbox, thinking off)
  → 复制件 Output → LLMTtsBridge.send_chat_segment → TTS
  → finalize → apply_step（完成/下一步/clear/yield）→ 分发其它工具
  → add_assistant_message + 长期记忆 + δ-mem → notify_ai_reply
  → 情绪更新（异步）
```

### 6.4 失望 / 重写 / clear

```
导演激活中，AutoTimer 又到期 → on_idle_trigger()
  silent_rounds+1
    < 3 → speak("idle_disappointed")：失望 + 只调当前这一步
    ≥ 3 → planner.plan(kind="rewrite")（重新抽素材，可能换视频）→ speak("rewrite")
任何 reply 回合 → silent_rounds = 0

clear（director_step.clear=true 或 全部 done）
  → LLMDirectorBridge.clear() → on_cleared（主链路 flush + 清导演副本历史）
  → 下一轮用户消息走 LLmCore.msg_deal（提示词里已无导演块）
```

## 7. 风险、取舍与已知取舍（必须一起看）

1. **每轮多一次判官调用**：这是你选的「每轮异步判」，成本≈一次小 `max_tokens`。可通过 `judge_enabled` 关掉；关掉后只剩「空闲触发时由规划器判」。
2. **两套 EWMA 水词分**：复制件是独立实例，达不到「和主链路同一个分数」。取舍：分词表（复制）、分分数文件（`llm_response_score_director.json`），避免两个实例并发写同一 JSON 丢更新。若你更在意「语气一致」，可选方案：复制件**只读**主链路落盘的最近一次分数做初值（需要主链路把分数写进一个共享小文件，属于额外改动，默认不做）。
3. **复制件与主链路会漂移**：以后改 `func/llm/output.py` 的水词/切段，不会自动同步到 `copied/`。取舍：这是「禁止直接引用」的代价；在 `copied/__init__.py` 顶部写死「改动必须两边同步」，并在验收清单里加一条。
4. **短记忆顺序**：靠「进入/退出导演各 flush 一次」根治（3.8）。漏掉这一步的后果很具体：退出后主链路的 json（旧）+ 内存（新）会倒序，提示词里出现时间错乱。这是本方案里最容易被实现者忽略的一条。
5. **折叠工具的可靠性**：模型可能只说话不打标。兜底三层：①块内硬规矩 + 工具描述；②`stall_turns`（默认 2）后补一次「只调 director_step」的小监工；③「全部 done」本地确定性清场。仍不保证 100%，但不会静默卡死（有 no-progress 日志）。
6. **`LLmState` 队列绕过**：导演引擎不走主链路队列，靠 `can_take_over()`（主链路 `is_ai_ready` + 队列空）避免与主链路同时开口；导演自己用 worker 队列串行化。
7. **工具二通道在导演期间被跳过**：当 `toolbox.fast_reply_direct_tool=false` 时，导演回合里的显式工具请求会退化成普通回答。当前配置是 `true`（合并模式开着），不受影响；要彻底解决需把二通道也接到导演（不建议本期做）。
8. **视频概率与消费**：`AutoRandomTopic.pick()` 的概率池原样保留；**只有计划真的开始才 `move_to_collect`**，避免规划失败把素材吞掉。
9. **重启**：默认不恢复旧计划（`resume_on_start=false`），避免几小时前的计划复活；文件保留备查。
10. **心理块空串的坑**：`_psyche_block` 现在的提前 return 会吞掉导演块，必须按 3.9 改。
11. **思考模式**：DeepSeek 配置开着 thinking，导演侧所有带 tools 的调用必须显式关思考；顺带记录 `inherit` 的既有隐患（不在本期修）。
12. **并发/重入**：判官与空闲触发可能同时到达；`_running` + 导演锁 + 「已激活就跳过判官」三重防护。
13. **`notify_user_message` 语义**：导演接管后主链路不再通知，必须由 responder 补发（否则 cold_time 计时不会重置，会连着触发）。
14. **不写测试文件到 `.temp`**：状态文件是程序自己读写的运行时缓存，验证脚本一律放系统临时目录或 `scripts/`。
15. **长计划的 token 成本**：按需求不做长度限制，导演激活期间每一轮提示词都会带整份清单。渲染上做两件不违背需求的事：已完成步骤压成一行、`reaction` 只留最近两条；规划提示词里提醒「步数够演完就行」。若以后发现成本过高，再讨论上限（不要现在偷偷加）。

### 12.3 落地时相对方案的 6 处细化（不改语义）

1. **`copied/message_builder.py` 多一个 `build_context()`**：主动开口（没有用户消息）不能伪造一条 user，用 system + 旧记忆 + 内存记忆组装。
2. **`responder` 的写入顺序**：先写助手侧记忆，再 `apply_step`。原因是 `apply_step` 判 clear 会立刻触发退出事件 → 归档副本短期记忆；如果先 apply 再写，最后这句会留在内存里丢掉。
3. **`start_bored` 的 uid**：取 `MeowLLMLtMemBridge().last_uid`（主链路每轮会更新）；取不到就退回主动回复提示词，避免后置词拼出「你现在在和说话」。
4. **`responder` 复刻了主链路 `pre_route`（本地硬触发）**：用户回合先走 `pre_route_plan`，命中「看屏幕 / 画图 / 插件会话」就派发工具、记一条用户短记忆并结束本轮，不出表演台词——否则导演期间这些确定性需求会被当成普通闲聊。破甲审查因此挪到 `pre_route` 之后，与主链路顺序一致。
5. **素材 `brief` 进导演块**：最初只在计划里留 `title/topic`，执行回合的提示词拿不到视频内容（只能靠 steps 里模型自己写的目标）。落地后补上 `material.brief`（视频=标题｜内容摘要，≤400字；回忆=话题（标签）），在块里渲染一行「由头：…（只是引子，不许照着复述，也不许一次讲完）」。完整素材仍然只喂规划器一次，执行阶段不重复喂全文；视频消费后计划里的 `path` 同步为收藏路径。
6. **实测后的引导修正**（真模型实测见 `DEMO_导演流程_2026-10.md` 第 7 节）：首轮实测里计划 4 步全是 meta（“抛个念头”“把话头递给他”），视频概括虽然每轮都在提示词里，但没有任何一步安排“讲具体哪一处”，执行时就只聊“你闷不闷”。因此：①`planner_prompt` 要求「素材是视频时至少一步写清具体画面/台词/我为什么在意」，红线改为「视频可以讲，但不许照简介复述、不许一次讲完」；②`director_step` 的 `completed` 改为「说出口就算完成，他没接不算没完成」，避免步骤因为用户不配合永远卡住；③导演块与 reply turn hint 加「这一步说出口就算完成」「要讲由头就讲具体那一处」。

### 13.6 自检时发现并修掉的点

1. `en.js` 里 `判官输出 tokens` 与主链路面板重名，重复定义 → 删掉重复项（保留原有一条）。
2. `QQDirectorCore` 一开始把 `QQDirectorConfig` 缓存在实例上；配置热重载是「原地重跑 __init__」，但模块重载会换类对象，缓存值会变旧 → 改成每次用时 `QQDirectorConfig()` 取。
3. 群聊导演钩子最初放在「意图分析」之前：天气/唱歌等工具消息会被分析消费、不会走回复，却可能先起一段戏 → 挪到破甲审查之后、真正回复之前。
4. `_build_plan` 遇到空白 step 会产生空走向 → 增加空步骤保护。
5. `advance` 最后一步完成时先 `store.set` 再 `clear`，避免 `turns` 没落盘。
6. store 读写改成 `deepcopy`，防止调用方原地改 steps 影响缓存。
7. 判官解析对 `function` 缺失/坏 JSON 做保护；总开关关闭时 `render_block` 直接返回空。
8. **实跑时发现**：没有走向时判官也可能填 `clear=true`，旧逻辑会因此拒绝起戏 → 改成「没有走向时忽略 clear，只看 cold + steps」；同时把随机抽到的由头提前给判官，让第一步直接拿它当话头（实测里 steps 会写「用《干物妹！小埋》那个视频起话头」）。
9. **关键词接入**：`director_on` 增加 `"关键词"`，关键词回复与 @ 同待遇（起戏/看块/推进）。
10. **主链路明确拒绝兜底**：判官只判“无聊”，不判“别烦”；`enqueue_user_turn` 里加窄词表兜底，命中即收尾并交回主链路，不再依赖模型记得打 `clear`。
11. **落盘/归档**：主链路和 QQ 的状态改到 `.temp/director_topic/`；clear 后归档到 `character/director_topic/` 并删除缓存；重写覆盖前归档旧计划；旧文件自动迁移。
