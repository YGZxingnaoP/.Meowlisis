# PLAN：清唱（无伴奏人声）静音段压缩方案

- 状态：已实施（2026-11-10）
- 适用模块：`func/toolbox/meowsongs`（即兴哼唱 + 听歌识曲接龙）
- 日期：2026-11

## 1. 问题

`impromptu_sing` 与 `pass_the_baton` 播放的是分离出来的 **vocal 轨**（`{title}_vocal.wav`），不带伴奏。
伴奏段在 vocal 轨里就是近乎无声——原来的前奏、间奏、尾奏、段落衔接全变成了**死气**，一次接唱里可能夹着十几秒静音。

实测（本地曲库 6 首，20 ms 帧、相对 p95 电平 −35 dB 判静音）：

| 指标 | 实测 |
|---|---|
| 全曲 vocal 轨静音占比 | 平均 **30%**（21.6%–36.8%） |
| ≥1 s 的长静音总时长 | 25–70 s / 首，最长单段 **6.5–27 s** |
| 典型 3 句切片静音占比 | 平均 **19.9%** |
| 典型切片时长 | 平均 10.2 s，句间小静音平均 0.33 s |

用拟定参数离线模拟（见 §5）：

| 场景 | 压缩前 → 后 |
|---|---|
| Snow halation 全曲 | 256 s → 186 s（−27%） |
| 含 17 s 间奏的 4 句切片 | 36.9 s → 19.8 s |
| 前奏区切片 | 17.3 s → 4.8 s |
| Love Story 全曲 | 236 s → 191 s（−19%） |
| Anytime Anywhere 全曲 | 231 s → 205 s（−11%） |

## 2. 空档从哪来（三个入口）

1. **切片内部间奏**：`next_line.locate()` 取 `offset+hum_duration` 之后的 `hum_lines` 句，句与句之间可能有整段间奏；`impromptu_sing._resolve_range()` 还有 "span < 3 s 继续加句" 的逻辑，会把间奏圈进来。
2. **切片尾部**：`pass_the_baton` 的 `end_sec` = 下一句起始，若后面是尾奏则整段静音；`impromptu_sing` 更直接：`end_sec = 末句时间 + max(2.0, 句长)`，固定多出 2 s 静音。
3. **切片头部**：LRC 时间戳早于人声实际起音，起手就是半秒空白。

## 3. 方案总览

新增一个纯函数式音频工具，两个播放路径各接一行；**不改任何落盘的曲库文件**，只在播放/发送前对该次切片做时间压缩。

```
LRC 定界 → 读切片 → 静音检测 → 生成切口表 cuts → 拼接（切口处留 250 ms 呼吸）
                                        └→ 时间映射 map_time() → 字幕时间戳重排
```

要点：

- 只压缩**静音**，人声一个采样都不丢，不改音高/时长比例，不用时间伸缩（WSOLA 会动音色，否决）。
- 切口处保留固定长度的"呼吸"（默认 250 ms，前后不对称：前 100 ms / 后 150 ms），听起来是正常换气，不是硬切。
- 全部参数进 `config.yml`；`enabled: false` 时行为与现在**逐字节一致**，方便 A/B 与回滚。

## 4. 算法

### 4.1 检测（每个切片独立做，O(N)，毫秒级）

1. 立体声下混为单声道用于分析，输出仍用原始声道。
2. 20 ms 不重叠帧算 RMS → dB。
3. 参考电平 `ref = percentile(db, 95)`；静音阈值 `thr = max(ref - rel_db, abs_db)`，默认 `rel_db=45`、`abs_db=-60 dBFS`。
   - 45 dB 是刻意保守：低到只可能是"伴奏空档/底噪"，小声唱不会被判成静音。
   - 绝对下限防止把分离残留的底噪当人声。
4. 双阈值迟滞（Schmitt，6 dB）：进入人声需 `> thr+6`，回到静音需 `< thr`，避免尾音/气声处闪烁。
5. 不做形态学腐蚀：低于 4.8 s 的静音一律不动（见 §4.2），换气、句间停顿原样保留。
6. 全静音兜底：整段都没有人声帧时只返回 0.2 s，避免播出一段死气。

### 4.2 切口与拼接

- **桥接**：夹在两段静音之间、短于 **120 ms** 且峰值低于 `ref − 20 dB` 的杂音，并入静音一起计算长度。分离残留里经常有 80 ms 的爆音，不桥接会把 9 秒空档劈成两段、白留一截静音；正常唱出的短音不会这么轻，所以不会被并进去。
- **段内静音**：只有连续静音 `> min_gap_sec`（默认 **4.8 s**）才切；切口为
  `[s + head_keep, e - tail_keep]`，默认 `head_keep = 900 ms`、`tail_keep = 1100 ms`，合计 **2 s** 呼吸。
  短于 4.8 s 的换气、句间空隙一律保留，避免"一有静音就切"的碎感。
- **片头/片尾静音**：不属于句间间隔，只做边界上限——片头最多留 900 ms、片尾最多留 1100 ms，超出部分裁掉（顺手消掉 `impromptu_sing` 那固定 2 s 尾巴）。
- **按切片读取**：`sf.info` 取总帧数与采样率，`sf.read(start=, frames=)` 只读需要的一段，不再为一次接唱解码整首 4 分钟的歌。
- 拼接：保留区间顺序拼接；接缝做 15 ms 线性淡变（切口在静音里，淡变只是保险）。

### 4.3 时间映射（字幕必须用，否则会越唱越不同步）

`cuts` 是唯一真值，音频拼接和字幕映射必须由同一份 cuts 生成：

```python
def map_time(t):
    shift = 0.0
    for a, b in cuts:
        if t <= a:
            break
        if t < b:            # 落在切口里 → 映射到接缝
            return a - shift
        shift += b - a
    return t - shift
```

`MeowLyricSyncer` 是按墙钟 + `lines[i].time - lines[start_idx].time <= elapsed` 推字幕的，
所以给 `play_audio` 传**重排后的相对时间**（首句 0，`start_idx=0`、`end_idx=len-1`），不要把绝对 LRC 时间原样传进去。

## 5. 参数（最终实施值）

| 配置项 | 默认 | 含义 | 调大 / 调小 |
|---|---|---|---|
| `meowsongs.squeeze.enabled` | `true` | 总开关 | 关 = 完全旧行为 |
| `min_gap_sec` | `4.8` | 连续静音超过该秒数才切 | 调小会开始切短换气，别低于 2–3 |
| `head_keep_sec` | `0.9` | 切口前（前一段末尾）保留的呼吸 | 调大更从容 |
| `tail_keep_sec` | `1.1` | 切口后（后一段开头）保留的呼吸 | 调大更从容 |
| `rel_db` | `45` | 静音阈值 = p95 − rel_db | 调大更保守（更不易误切小声唱），调小切得更狠 |
| `abs_db` | `-60` | 绝对静音下限（dBFS） | 底噪高的曲库可上调到 −55 |

模块内固定：分析帧 20 ms、迟滞 6 dB、桥接 120 ms（低于 `ref − 20 dB` 才算杂音）、接缝淡变 15 ms。

## 7. 边界与兜底

- **整段没人声**（用户哼到间奏、或对齐点落在间奏）：只返回 0.2 s，不播长段死气；`impromptu_sing` 的音高缓存与匹配不受影响。
- **小声唱**：阈值取 45 dB 相对 + −60 dBFS 绝对，且短于 4.8 s 的静音一律不切，弱唱不会被咬；若曲库底噪偏高，把 `abs_db` 上调（如 −55）反而更保守。
- **极端长间奏**（> 10 s）：压到 2 s 呼吸后确实会有"跳段"感，属于清唱形态本身；需要更连贯可把 `head_keep_sec`/`tail_keep_sec` 调大。
- **立体声、采样率**：分析用下混，切片按原声道拼接；不重采样（`play_audio` 自己按 sr 走）。
- **并发/打断**：纯函数，无状态，`_busy` 锁与 TTS 队列语义不变；播得短了，`_wait_tts_idle` 自然也短。
- **异常**：`squeeze` 内部 try/except 兜底，失败返回原音频 + 空 cuts（等于旧行为），不因音频处理炸掉接唱。

## 8. 分阶段

- **P1（已完成）**：`vocal_squeeze.py` + 两个播放路径接入 + 配置/面板/i18n + 合成信号自测。
- **P2（可选）**：学歌时预计算全曲人声活动图（`{title}_vad.npy`，20 ms 帧 uint8），播放时与切片求交。
  - 好处：`next_line` 可以跳过"整句都落在间奏里"的行、起唱点吸附到真实人声起点；缺点：多一个缓存文件与失效判定。
  - 只有在 P1 听感仍不够、或想进一步优化歌词对齐时再做。
- **P3（可选）**：F0 辅助判定（`librosa.yin`，与 `hum_match` 同源），替换纯能量 VAD，进一步降低"弱唱被误切"的概率。成本是每切片几十到几百毫秒。

## 9. 验证

1. **合成信号自测**（不读曲库，秒级）：6 s 空档 → 切 4 s 留 2 s；3 s 空档 → 不切；5 s 小声唱（−52 dBFS）→ 不切；首尾长静音 → 只留 0.9/1.1 s；全静音 → 0.2 s；字幕映射单调且切口后整体前移。
2. **回归**：`enabled: false` 时输出与改动前一致（原音频原样返回）。
3. **字幕**：接唱/哼唱时歌词切换点与听到的句子偏差 < 150 ms（人工看 3 首）。
4. **QQ 语音**：`meowsongs_baton.wav` / `meowsongs_latest.wav` 时长与本地播放一致（压缩后同步变短）。
5. **性能**：单次 `squeeze` 20 s 切片为毫秒级（numpy + 一次帧循环），实际延迟可忽略。

## 10. 风险

- 阈值过激 → 弱唱被咬：默认 `rel_db=45` 已很保守，且短于 4.8 s 不切；出问题只调配置，不改代码。
- 接缝轻微不自然：切口都在静音里 + 15 ms 淡变，风险低；必要时把 `head_keep`/`tail_keep` 调大。
- 字幕不同步：必须用同一份 `cuts` 生成映射（§4.3），不要另写一套时间换算。
- 回滚：`enabled: false` 即恢复旧行为，无迁移成本。
