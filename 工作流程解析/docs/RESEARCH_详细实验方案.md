# 第 0 部分：先把"彻底解耦"形式化（这决定了后面所有实验变量）

## 0.1 解耦的两种形态（必须先定，否则实验无法设计）

| 形态 | 定义 | 隐藏状态可否共享 | δ-mem 可否直接耦合 |
|---|---|---|---|
| **形态 A：单骨干 + 两套 LoRA** | 骨干**仅 1 份**（冻结 φ 共享）；思考步挂 LoRA_think、输出步挂 LoRA_talk（两组参数不重叠） | ✅ 共享（同一前向） | ✅ 可直接耦合 |
| **形态 B：两个独立模型** | 骨干**2 份**：思考用一个模型 φ_T，输出用另一个模型 φ_K | ❌ 隐藏状态不同空间 | ⚠️ 只能经"桥"（learned bridge）或文本 |

> 骨干份数：形态 A = **1 份**；形态 B = **2 份**。**同一骨干上挂几套 LoRA 都只算 1 个模型。**

**结论：本计划默认【形态 A】**。理由：
1. 只有共享骨干，δ-mem 的"读取→注意力低秩修正"才能在**思考步与输出步里都直接生效**（否则 Talker 拿不到 Thinker 的隐藏状态）。
2. "参数彻底解耦"在形态 A 下依然成立：**两套 LoRA 参数（思考步/输出步）完全分离，只有 frozen backbone + 记忆基底 S 共享**。
3. 论文里把"形态 B 的桥接"作为**附加实验**（证明不共享骨干时性能下降，从而论证共享记忆基底的必要性）。

> 若你坚持形态 B（两个模型），第 0.4 节给"桥接"方案；但主实验走形态 A。

## 0.2 记忆基底 S 的形态（"矩阵"要改的地方）

原 δ-mem：每层一个 `S ∈ R^{r×r}`。解耦后需要升级为**带步骤标签的记忆银行**：

```
S = { S^{(l, u, slot, tag)} }
  l    : 层
  u    : 用户（呼应你的"每用户 128×128"）
  slot : 主题槽（MSW，复用你的 topics：日常/爱好/哲思/闲聊/情感）
  tag  : 步骤标签 ∈ {intent(思考步写入), utterance(输出步写入)}
```

**读写公式（带步骤条件门控）**：
```
qm, km = l2norm(tanh(Wq^m x + e_step)), l2norm(tanh(Wk^m x + e_step))
vm     = Wv^m x
beta   = sigmoid(Wb (x ⊕ e_step) + b)      # 步骤条件门控：思考步/输出步写入门不同
lam    = 1 - beta

r       = S^{(l,u,slot,tag_read)} @ qm                    # 步骤条件读取
dq, do  = Wdq^step @ r, Wdo^step @ r
q~      = q + (alpha_step / r_dim) * dq
y~      = Attn(q~, K, V) + (alpha_step / r_dim) * do
S^{(l,u,slot,tag)} = Diag(lam) S + Diag(beta) outer(vm - S@km, km)   # delta 写
```

**三处关键改动**：
1. **状态不再唯一**：从"单状态"变为"多状态银行"（per-layer × per-user × slot × step-tag）。这与 δ-mem 论文的 **MSW** 一致（论文也发现小模型用多状态能减少干扰）。
2. **门控按步**：`β, λ` 的输入拼上步骤嵌入 `e_step` → 思考的写入门 ≠ 输出的写入门。
3. **key 带步骤标签**：`k = [k_content ; step_emb]`，使读取可寻址"意图"或"已说出的话"。

## 0.3 为什么"解耦"会制造一个**新的技术问题**（=论文新贡献）

参数解耦后，思考步与输出步各自优化，但**共享记忆 S**。于是：
- **思考步的写入**要服务**未来的输出步**（跨步、跨轮）；
- **输出的写入**要反映"实际说了什么"，供**下一轮思考**使用；
- 二者的接口（focus 文本、S 的读出）如果 stop-gradient，就没有端到端信用；如果不 detach，又难稳定。

→ 这就是 **跨步信用分配（cross-step credit assignment）** 问题。
**它不是障碍，而是论文的技术核心（记作 N7）**：如何在参数不相交的两套 LoRA 间，训练共享的注意力记忆基底。

## 0.4 训练方式的三种候选（对应你的"训练方式要改"）

| 方案 | 机制 | 优点 | 缺点 |
|---|---|---|---|
| **T1 分离目标 + detach 接口** | Thinker 训"写有用性"，Talker 训 CE，接口 detach | 稳定、易复现 | 无端到端信用，N1 弱 |
| **T2 交替优化** | 冻结 T 训 K → 冻结 K 训 T（用 K 的损失下降做 T 的奖励） | 有信用、实现中等 | 需两阶段、可能震荡 |
| **T3 ELBO 桥接**（借 FLAIR） | 非因果专家给后验（"理想写入"），因果步骤 KL 对齐 | 有理论、无需显式标注 | 工程重、专家训不稳 |

**推荐 T2 + 写有用性对比损失**（见 §1.2），理由：直接检验 **N1（思考作为写策略）**，且可证伪。

损失（阶段二联合）：
```
L = L_talker_CE(Y | Q, focus, S)                 # 输出的自回归
  + λ1 * L_write_useful(S)                        # 写有用性（对比：正确下一轮记忆 vs 干扰项）
  + λ2 * L_align(focus, S readout; sg)            # 步骤接口对齐
  + λ3 * L_time(think/talk 二分类)                # 何时思考/何时说（借 FLAIR 的 Ĝ）
L_write_useful = -log exp(sim(read(S,Q+), m+)) / Σ exp(sim(read(S,Q+), m_j))
```

## 0.5 注意力机制微调的三处改动（对应你的"注意力机制要改"）

1. **两套按步投影、一套共享状态**：`Wdq^step, Wdo^step` 分步骤；`S` 共享 → 形成"记忆总线"。
2. **注入分支分步骤**：思考 → 只注入 **q**（为规划检索历史）；输出 → 注入 **q 和 o**（为"说得好"）。消融验证。
3. **插入深度分步骤**：思考 → **middle**（抽象层）；输出 → **all**（复现层）。消融验证。
4. **时序契约（N3 闭环）**：
   ```
   本轮:  思考 读S → 写S(intent) → 输出 读S(intent) → 说 → 写S(utterance)
   轮间:  输出结束后 思考继续 读S(utterance) → 更新 plan_next → 写S(intent') ...
   ```
   必须保证：Talker 能读到本轮 Thinker 的写入；下一轮 Thinker 能读到上一轮 Talker 的写入。

# 第 1 阶段：模型级验证（Model-level）

**目标**：证明改造后的前向/损失**可训练、可收敛、行为正确**；按步记忆总线结构无泄漏。
**不需要真实数据**——用**受控合成任务**，几天即可跑完（1×24G）。

## 1.1 单元/不变量测试（必须全绿才进入下一阶段）
| 测试 | 做法 | 通过标准 |
|---|---|---|
| 梯度流向 | 反向传播后检查各参数 `.grad` | 只有 δ-mem + 两套 adapter 有梯度；backbone 全 None |
| 状态稳定性 | 长流（10k token）跑 S 更新 | `‖S‖` 有界；无 NaN/Inf（L2norm 已用于抗漂移） |
| 步骤隔离 | 关闭 step 掩码，观察读取 | 步骤读取结果与合并读取显著不同（证明门控真的起作用） |
| 参数计数 | 统计可训练参数量 | 与 δ-mem 论文量级一致（~0.12% backbone） |

## 1.2 合成任务（证明机制"能工作"）
1. **联想召回（associative recall）**：注入 N 组 `key→value`，移除明文，只留 S；用 key 查询 → 必须召回 value。
   - 指标：`recall@1`，随 N 的衰减曲线。
2. **写入策略有效性（测 N1）**：同一批记忆，两种写入：
   (a) 确定性写入（按 token/segment，δ-mem 原版）；(b) **思考选择后写入**（Thinker 决定写什么/何时写）。
   - 指标：后续任务的召回/准确率。
   - **若 (b) ≤ (a) → N1 不成立，论文降级**。这是最早、最便宜的一次"生死判定"。
3. **记忆总线闭环（测 N3）**：Thinker 写入 intent → Talker 读取并生成 → Talker 写 utterance → 下一轮 Thinker 读取。
   - 指标：下一轮预判命中率（回顾性判断"Thinker 预测的计划是否与实际的下一轮相关"）。
   - 对照：无总线 / 单向总线（只能 T→K）。
4. **写入粒度对比**：TSW / SSW / MSW 在对话式数据上的召回与抗噪。

## 1.3 产出与证伪
- 产出：收敛曲线、S 稳定性曲线、写入策略对比柱状图。
- 证伪：不收敛 / S 爆炸 / 写入策略无差异 / 闭环无增益 → 停在此层修设计。

# 第 3 阶段：多用户验证（Per-user matrix）

**目标**：证明"每用户 128×128"能**互不干扰、可增量写入、随用户数可扩展**。

## 3.1 实验
| 实验 | 做法 | 指标 | 证伪 |
|---|---|---|---|
| 跨用户污染 | N 用户各自事实，问 A 时统计 B 事实出现率 | pollution rate | >0 且显著 → 失败 |
| per-user vs 共享 | 同数据两配置 | per-user 召回 | per-user ≤ shared → 失败 |
| 规模曲线 | N=2/5/10/50 用户 | 召回随 N 的衰减斜率 | 陡降 → 不可扩展 |
| 增量写入 | 新记忆后立即询问；并查旧记忆 | 生效率 / 遗忘率 | 写了不生效 or 冲掉旧的 |
| 路由精度 | 门控选中正确状态的比例（CLS 式赢者通吃） | routing acc | 低 → 门控键设计差 |
| 主题分槽 | slot=1 vs slot=5（MSW） | 污染/召回 | 分槽无益 → 去掉 MSW |

## 3.2 你的"128×128"三种实现的横向对比

→ 对比：参数、召回、污染、增量写入成本。**给出一张"该用哪种"的决策表**（论文实用贡献）。

   □ 污染率 / 规模曲线 / 增量写入 / 路由精度
   □ 128×128 三种实现对比 → 决策表
□ 第4阶段（1~2周）
   □ 离线回放 + 在线 A/B 盲评 + 失效剖析
□ 边做边写：每完成一个消融 → 一张图/表 → 拼论文

## 附：必须先定的一件事
**形态 A 还是形态 B？**（单骨干+两套LoRA / 两个独立模型）
- 选 A：δ-mem 直接耦合，实验按本文走；"解耦"体现为两套 LoRA 参数与目标分离。
- 选 B：需额外的 learned bridge（把 Thinker 隐藏态映射到 Talker 空间），δ-mem 只能挂在各自骨干上，
  **共享 S 需要显式对齐损失** —— 这本身可成为论文的第二个技术点，但实验量与风险翻倍。

我的建议：**主实验走 A，把 B 作为附加对比（证明"共享基底"不可替代）**。
