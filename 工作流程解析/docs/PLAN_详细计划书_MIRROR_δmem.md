## 0. 全局前提与约定（开工前必须先读）

### 0.1 架构形态约定：**形态 A**（单骨干 + δ-mem 旁路 + 共享记忆银行；两套行为 LoRA 可选、归阶段 4）

| 形态 | 骨干份数 | 构成 | 隐藏状态 | 能挂 δ-mem | 本计划 |
|---|---|---|---|---|---|
| MIRROR 形态 | 0（调 API） | 外部 API，仅靠 prompt 分思考/输出 | ❌ | ❌ | 阶段 1 用它做对照 |
| **形态 A（采用）** | **1** | 1 份冻结自托管骨干 + δ-mem 旁路（**唯一必训**）+ **可选**两套行为 LoRA（思考步/输出步，见 §4.1.1） | ✅ 共享 | ✅ 可直耦 | **主实验** |
| 形态 B | 2 | 两个独立模型 | ❌ 不同空间 | ⚠️ 需桥接 | 仅作附加对照 |

**结论**：主实验走 **形态 A**。理由：问题①约 80% 靠框架（编排）解决，A/B 无差别；问题②只有 δ-mem 能解，而 δ-mem 必须挂在**自托管骨干**上并拿到隐藏状态。
> ⚠️ **重要修订**：形态 A 里原写的"两套 LoRA（思考步/输出步）"**不是机制必需**，本质是**风格/行为特化**，已**降级延后到阶段 4**（见 §4.1.1）。**阶段 2/3 的核心只有 δ-mem 旁路**，思考/输出步仅用 prompt 区分（MIRROR 原生做法）。

### 0.2 基座模型与算力前提

- **小模型验证**（阶段 1–3）：`Qwen3-0.6B`（冒烟）/ `Qwen3-1.7B`（主验证）/ `Qwen3-4B-Instruct`（对标 δ-mem 论文数值）。原因：δ-mem 论文已在 3B–8B 上验证（Qwen3-4B 46.79%→51.66%），可直接比数字；1.7B 是"能收敛 + 快迭代"的甜点。
- **实机落地**（阶段 5）：`Qwen3.8-27B`（原生多模态、稠密、262K 上下文）。稠密 27B 是**成本敏感点**（见附录 B）。
- **成本红线**：AutoDL 按量计费（参考：RTX 4090 24G ≈ ¥1.5–2.5/卡/时；A100 40G ≈ ¥3–4/卡/时；A100 80G ≈ ¥6–9/卡/时；会员 95 折）。**所有实验默认"能省则省"，用小模型先证伪，只有方向成立才上 27B。**

### 0.3 三条论文级「生死门」（Go/No-Go）总表

## 阶段 1　mirror 框架验证（**纯编排、无任何训练**）

### 1.0 阶段目标

> 关键：这一阶段**完全不碰模型**（思考步/输出步仅靠 prompt 区分），可直接在你现有的 OpenAI 兼容 API 上开发验证，见效最快、成本最低。

### 1.1 算法验证（对应你的 1.1：基于 qwen 开源小模型的算法验证）

**要在算法层面验证"焦点锁 + 每轮重构 + 跨轮延续"三条机制是否真的生效。**

| 验证项 | 做法 | 通过标准 |
|---|---|---|
| 焦点锁生效 | Talker system 注入"只回应 `{focus}`"，对比无 focus | 回复只落在 focus 的比例显著↑ |

| 状态机正确 | IDLE→TALK→THINK→IDLE 迁移、salience 门控 | 连续 200 轮不阻塞/不丢状态 |

**实现骨架（`func/thinker/` 新增，不改 `func/**` 编排层）**
```

挂接点：llm/llm_core.py::_ai_response 开头读状态注入、末尾起后台线程
升级：llm_active/inherit/inherit_core.py（已是跨轮延续雏形 → "延续思考"）
```
**ThinkState 数据结构**
```json
{
  "user_id": "...",
  "focus": "一句话：本轮只该聊什么",
  "thinking": "滚动摘要（内部，禁止复述，≤200字，每轮重写）",
  "plan_next": ["下一轮可能想说的点", "想问的问题"],
  "open_threads": [{"topic": "...", "status": "...", "next": "..."}],
  "salience": 0.0,
  "updated_at": "ISO8601"
}
```

## 阶段 2　δ-mem（**64×64**）验证

> 64×64 即 `r=64`，`S∈R^{64×64}`（4096 参数/层）。这是"单状态、单用户、单槽"的**最小可验证形态**。
> **本阶段不涉及任何 LoRA**，只训 δ-mem 旁路。

### 2.0 阶段目标
在最便宜的小模型上，证明 **δ-mem 注入注意力能被训练、能收敛、且记忆真的进注意力（no-context 增益）**。

### 2.1 算法验证（对应你的 2.1：基于小模型验证的算法验证）

**模型改造（核心，必须自研）**——替换 Qwen3 每层 attention 为 `DeltaMemAttention`：

```python
# 读
qm, km = l2norm(tanh(Wq_m·x)), l2norm(tanh(Wk_m·x))
vm     = Wv_m·x
beta   = sigmoid(Wb·x + b);  lam = 1 - beta
r      = S_prev @ qm                       # 读出
dq, do = Wdq @ r, Wdo @ r                  # 低秩修正
# 注入
q'     = q + (alpha/r) * dq                # query 分支
y'     = Attn(q', K, V) + (alpha/r) * do   # output 分支
# 写（门控 delta）
S      = Diag(lam) @ S_prev + Diag(beta) @ outer(vm - S_prev @ km, km)
```
- **只训**：`Wq_m, Wk_m, Wv_m, Wb, Wdq, Wdo, S_0`；**骨干全冻结**。
- 默认超参：`r=64`、`alpha=16`、**q/o 分支**、**全层**；V0 版 `S` 更新可先放 `no_grad`。

**不变量/单元测试（必须全绿才进 2.2）**

| 测试 | 做法 | 通过标准 |
|---|---|---|
| 梯度流向 | 反向传播查各参数 `.grad` | 只有 δ-mem 有梯度；backbone 全 None |
| 状态稳定性 | 长流 10k token 跑 S 更新 | `‖S‖` 有界；无 NaN/Inf |
| 步骤/参数计数 | 统计可训参数量 | ≈0.1%~0.12% backbone |
| 数值安全 | l2norm 抗漂移验证 | 不爆炸 |

**合成任务（受控、便宜）**
1. **联想召回**：注入 N 组 `key→value`，删明文只留 S，用 key 查询 → `recall@1` 随 N 衰减曲线。
2. **写策略对照（测 G1）**：确定性写入 vs 思考选择写入 → 后续召回。
3. **写粒度对比**：TSW / SSW / MSW 在对话数据上的召回与抗噪。

### 2.2 效果验证（对应你的 2.2：基于小模型的效果验证）

| 实验 | 对照 | 指标 |
|---|---|---|
| δ-mem vs Vanilla | 冻结骨干、无记忆 | 记忆问答准确率 |
| δ-mem vs 文本记忆 | BM25 RAG / 全塞 prompt | 准确率 + prompt token 数 |
| **no-context 测试（G2）** | 移除历史明文，只留 S | 准确率（论文：HotpotQA EM 0.08→6.48；LoCoMo 3.49→8.05） |
| 参数效率 | δ-mem vs MLP-Memory | 可训练参数 / 显存 / 吞吐 |
| 自身消融 | 插入层(all/mid/front/back)、分支(q/o/qo)、r(8/16/32/64)、α(8/16/32) | all 最优、qo 性价比最高 |

### 2.3 🚦 Go/No-Go · 交付物 · 工期 · 成本
- **门 G2**：no-context 显著 > 无 S 基线 → 记忆进注意力成立；否则回炉机制。
- **交付物**：① `DeltaMemAttention` + patch；② `build_data.py` 切窗脚本；③ `no_context_test.py` + 200 条评测集；④ 收敛/稳定性/召回曲线；⑤ 形态对比表（基座 / +δ-mem）。
- **算力**：单卡 24G（1.7B/4B），工期 1.5–2 周 ｜ **≈ ¥100–300**。

## 阶段 3　δ-mem（64×64）× mirror 的综合实验

> 把阶段 1 的框架与阶段 2 的记忆**接起来**。**本阶段仍不涉及 LoRA**：think/talk 是"步骤"（prompt 区分），
> δ-mem 的按步门控只作用于记忆读写，与是否有行为 LoRA 无关。

### 3.1 小模型算法验证：针对 **think / talk 状态**对 δ-mem 的验证（对应你的 3.1）

**核心：记忆银行 S 升级为「带步骤标签」的多状态，并验证按步门控是否必要。**
> 说明：这里的 think/talk 指**步骤标签**（用不同 prompt 触发），**不需要 LoRA**；两套行为 LoRA 属风格层，见 §4.1.1。

```
S = { S^{(l, u, slot, tag)} }
  l    : 层
  u    : 用户
  slot : 主题槽（MSW，复用你的 topics：日常/爱好/哲思/闲聊/情感）
  tag  : 步骤标签 ∈ {intent(思考步写), utterance(输出步写)}
```
**按步读写（门控拼上步骤嵌入 e_step）**
```
qm, km = l2norm(tanh(Wq_m·x + e_step)), l2norm(tanh(Wk_m·x + e_step))
beta   = sigmoid(Wb·(x ⊕ e_step) + b)         # 思考写入门 ≠ 输出写入门
r      = S^{(l,u,slot,tag_read)} @ qm          # 按步骤寻址（读 intent / 读 utterance）
dq, do = Wdq_step @ r, Wdo_step @ r
```
**时序契约（跨轮闭环，测 N3）**
```
本轮：思考 读S → 写S(intent) → 输出 读S(intent) → 说 → 写S(utterance)
轮间：输出结束后 思考继续 读S(utterance) → 更新 plan_next → 写S(intent')
```

| 验证项 | 对照 | 检验 |
|---|---|---|
| 共享 S vs 分步专属 S | shared-S / step-S / 双向总线 | 记忆总线是否优于隔离 |
| 步骤条件门控（有/无） | 共用 β,λ | 按步改动是否必要 |
| 注入分支分步骤 | 同分支 / 分分支（think 只注入 q、talk 注入 qo） | 改动是否必要 |
| 插入深度分步骤 | 同深度 / 分深度（think→middle、talk→all） | 同上 |
| 训练方式 | T1 detach / T2 交替 / T3 ELBO | **跨步信用分配 N7** |
| 写策略 | 确定性 / 思考选择 | **G1 / N1** |

**训练方案（跨步信用分配）**
```
L = L_talker_CE(Y | Q, focus, S)
  + λ1·L_write_useful(S)         # 对比：正确下一轮记忆 m+ vs 干扰项 m_j
  + λ2·L_align(focus, S; sg)     # 步骤接口对齐（stop-gradient）
  + λ3·L_time(think/talk)        # 何时思考、何时说
```
推荐 **T2 交替优化**：冻结 LoRA_talk 训 LoRA_think → 冻结 LoRA_think 训 LoRA_talk（用输出步损失下降当奖励）。
> 注：若未启用两套 LoRA（§4.1.1 判定不需要），T2 退化为"交替优化 prompt 两侧的 δ-mem 写/读投影"，机制不受影响。

## 阶段 4　准备训练数据 + LoRA 必要性决策

### 4.1 先确认：**是不是真的需要 LoRA？**（对应你的 4.1）

> 你的判断是对的：**MIRROR 对模型本身没有要求（纯编排），只有外挂 δ-mem 需要训练。**
> 下面把它拆成可判定的结论。

**分组件拆解**

| 组件 | 是否需要训练 | 需要训什么 | 是否需要骨干 LoRA |
|---|---|---|---|
| MIRROR 框架（编排） | ❌ 不需要 | 无（prompt + 状态机） | **不需要** |
| δ-mem（记忆进注意力） | ✅ 需要 | `Wq_m,Wk_m,Wv_m,Wb,Wdq,Wdo,S_0`（旁路，≈0.1%） | **不需要**（骨干冻结） |
| Talker 行为（短句/贴话题/口吻） | ⚠️ 可选 | 行为微调 | **可能需要** |
| 两套 LoRA 分离（形态 A 的 think/talk） | ⚠️ 条件需要 | 步骤专用适配 | 需要（仅论文 N7 需要） |

**结论（关键判断）**
1. **δ-mem 本身不依赖骨干 LoRA**：它只训旁路参数，骨干全程冻结。这是 δ-mem/CLS 论文的共同结论。
2. **框架层（MIRROR）零训练**：阶段 1 已证明，纯 prompt + 状态机。
3. **是否需要 LoRA，取决于一个可测问题**：*冻结的 Qwen3.8-27B 光靠 system prompt，能否稳定做到"只回应焦点、短句、不复述"？*
   - 若 **能** → **完全不需要 LoRA**，只训 δ-mem 旁路即可（省钱、省事）。
   - 若 **不能**（27B 仍爱求全/铺陈）→ 只加 **talk-LoRA**（行为微调），think 侧继续走框架。
   - **两套 LoRA 分离**只在你要主张论文贡献 N7（跨步信用分配）时才必须。

**🚦 决策门 P4（务必先跑，避免无谓成本）**
```
实验：冻结 27B/小模型 + 完整框架 + 只训 δ-mem 旁路（no-LoRA 对照）
 ├─ 焦点命中率 / 记忆使用率 达标  → 【不需要 LoRA】，直接进阶段 5 的 δ-mem 实机
 └─ 不达标                       → 加 talk-LoRA，重测
```
> **成本理由**：27B 的 LoRA 训练是整条链路里最贵的一步（见附录 B），**能不训就不训**。

### 4.1.1 两套 LoRA 到底是什么？（= 风格 / 行为特化，故归本阶段）

**定义**（引自 `PLAN_框架与模型训练.md` B3、`训练极小模型验证.md` G4）

| 名称 | 挂载时机 | 作用 | 本质 |
|---|---|---|---|
| **LoRA_think（思考步用）** | 只在"思考步"前向时挂载 | 让骨干产出**结构化内心独白/规划**（Goals/Reasoning/Memory → `focus`/`plan_next`） | 行为特化：让模型"会想" |
| **LoRA_talk（输出步用）** | 只在"输出步"前向时挂载 | 让骨干产出**短句、只贴焦点、像人**的对外回复（口吻/称呼/禁忌） | 行为特化：让模型"会说" |

**挂载方式（参数不重叠，共享同一冻结骨干）**
```
思考步：y = φ(x) + Δφ_think(x)     # 只挂 LoRA_think
输出步：y = φ(x) + Δφ_talk(x)      # 只挂 LoRA_talk
```

**三个要点**
1. 它们是"**把用 prompt 区分的两个角色，升级为用参数区分的两个角色**"——**本质是风格/行为层**，不是新机制。
2. **不是 δ-mem 的必要条件**：思考/输出步完全可以像阶段 1 那样**只靠 prompt 区分**（MIRROR 原生做法）。δ-mem 只训旁路，与 LoRA 无关。
3. **两个目标要分开处理**：

| 目标 | 是否需要两套 LoRA | 处理位置 |
|---|---|---|
| **工程/产品**（解决两个原始问题） | ❌ 不需要（能不做就不做） | 本阶段 4 决策门 |
| **论文贡献 N7**（参数不相交的两套 LoRA 如何共享/训练记忆基底） | ✅ 必须 | 论文实验时再启用 |

> **结论**：两套 LoRA = **风格/行为特化** → 从"形态 A 的架构定义"**降级为本阶段的可选决策项**。
> 阶段 2/3 的核心只保留 δ-mem；是否需要 LoRA，由本阶段的决策门决定。

### 4.2 数据准备「简单要求」（你要的目标要求）

> 目标：**统一成一个样本格式，从现有资产自动切窗**，Part A（框架）/Part B（δ-mem）/LoRA 三种用途共用一套数据。

**输入源（全部复用现有资产，不改语义）**
```
character/memory/*.txt                     → 原始对话轮次 (user/assistant, 时间, 用户名)
character/abstract_memory/meow-*.json      → 记忆条目 C (event/tags/topics/evidence)
character/info/users_info/*_latest.json    → 用户档案（S_0 初始化 / 门控键）
character/front/*.json                     → 人设/约束
```

**统一样本格式**
```
{user_id, time, history[], query(Q), response(Y),
 memories(C), profile{}, focus, plan_next{}}
```

**三条硬性要求**
1. **切窗**：以每条 AI 回复为锚点，前 N 轮为 `history`，同用户记忆条目为 `C`；`Q`=本轮用户消息，`Y`=本轮 AI 回复（清洗后文本）。
2. **划分**：**按时间切**，后 10% 做验证，**严禁同用户泄漏**（同一用户必须整段落在同一侧）。
3. **中立化**：为论文/对外，单独构造**无 NSFW 的中性人设**子集；原始人设数据只用于内部实机。

**量级要求**

| 用途 | 建议样本量 | 说明 |
|---|---|---|
| V0 探路（阶段 2/3） | 2k–5k 条 | 只为验证机制，不求效果 |
| 全量训练（阶段 5 δ-mem） | 1w–5w 条 | 1 epoch 足够 |
| talk-LoRA（**若**决策门判定需要） | 1w–5w 条 | 只取"焦点一句"清洗后的回复 |

**评测集（阶段 2 起就必须先有）**
- 200 条 **no-context** 测试（删 `C` 明文问 `Q`；再只留 `S` 问）。
- 200–500 条 **焦点命中**评测（回复是否只落在 focus）。
- 多用户**交叉污染**测试（A/B 用户事实互查）。

**交付物（数据侧）**：`build_data.py` 切窗脚本 + 生成的 jsonl（train/val）+ 三套评测集。

### 4.3 数据准备 Checklist（照着打勾即可）
```

```

## 阶段 5　基于 **Qwen3.8-27B** 的实际训练与落地

> 前提：阶段 1–3 的门全绿；阶段 4 决策门已给出"是否需要 LoRA"的结论。

### 5.1 训练（对应你的 5.1）

**训练对象（默认，无需骨干 LoRA 的情形）**
- 只训 **δ-mem 旁路**：`Wq_m,Wk_m,Wv_m,Wb,Wdq,Wdo,S_0`（≈0.1% 参数），骨干冻结。
- 若阶段 4 判定需要行为微调 → 追加 **talk-LoRA**（rank 8–16，q/v_proj，`lr=1e-4`，1 epoch，小步防退化）。

**基座适配要点（27B + 多模态）**
- Qwen3.8-27B 是**原生多模态**：attention 同时处理文本 token 与视觉 token → `DeltaMemAttention` patch 必须**只对文本/对话 token 生效**，视觉 token 直通，避免污染。
- 262K 上下文：训练时按实际对话长度截断（一般远小于），不需要拉满上下文。
- 改造后**标准 vLLM/llama.cpp 用不了** → 用 HF `generate` + 自定义 attention 跑通；性能不足再上 vLLM 自定义插件。

**训练配置（模板）**
```
基座: Qwen3.8-27B   冻结
可训: δ-mem 投影 (+ 可选 talk-LoRA)   ~0.1% 参数
loss: CE(Y | Q, S_C) + λ·焦点一致性(可选)
epoch: 1   有效 batch: 32   precision: bf16
lr: 2e-4  cosine  warmup 0.1   optimizer: fused AdamW
分布式: DeepSpeed ZeRO-2 (或 ZeRO-3) / QLoRA(4bit) 省显存
```

**27B 显存与卡型建议（AutoDL）**

| 方案 | 配置 | 显存 | 说明 |
|---|---|---|---|
| A 省钱 | **QLoRA 4bit + ZeRO-2**，1×A100 40G 或 2×4090 24G | ~18–20G | 自定义 attention + 4bit 需谨慎调试 |
| B 稳妥 | **bf16 LoRA + ZeRO-2**，2×A100 80G（160G） | 权重 54G | 推荐，稳定 |
| C 折中 | **bf16 + ZeRO-3**，4×4090 24G（96G） | 分片 | 便宜但慢 |

### 5.2 mirror 框架实现 + δ-mem（**128×128**）实机实施（对应你的 5.2）

**A. mirror 框架实现（复用阶段 1 成果，接到 27B）**
- `func/thinker/` 三模块 + `ThinkState` 落盘（每用户一份）。
- 挂接点：`llm/llm_core.py::_ai_response`（读状态注入 / 起后台思考线程）；升级 `inherit_core.py` 为"延续思考"。
- Talker system 分区：`内心（禁复述）+ 焦点（必遵守）+ 行为约束（否定式）+ 少量记忆`。

**B. δ-mem（128×128）实机实施**
- `S_u ∈ R^{128×128}`（16,384 参数/层/用户）；干扰大时用 **MSW**（如 4×`64×64` 分槽，复用 topics）。
- **门控键**：用现有 **bge-m3 端口**编码用户/主题 → `g_i = δ(i, argmax_j cos(e_j, e_cue))`，赢者通吃。
- **CLS 门控 LoRA（可选补充）**：MLP down-projection 中间层，masked rank-2，~2–3 参数/token，多用户互不污染、可增量写入。
- **部署**：`func/llm/port/local.py` 新增本地 port → 本地 OpenAI 兼容服务（模型侧挂 hook）。

**C. 灰度与回滚**
```
shadow（只记录不生效）→ 小流量 A/B（按用户分流）→ 全量
开关：think_enable / delta_mem_enable / per_user_enable
异常回退：切回原 API port
```

**D. 埋点**：偏题率、记忆使用率、no-context 抽样、延迟 p50/p95、显存；每题记 traceid。

### 5.3 效果体验（对应你的 5.3）

| 你的问题 | 指标 | 基线 → 目标 |
|---|---|---|
| 回复不跟话题/求全 | 偏题率、平均句数、句长分布 | 偏题率 ↓ ≥ 20pt |
| 记忆用不起来 | 记忆使用率、关键记忆召回、no-context | 显著↑ |
| 说话方式 | 句长 / 水词密度（复用 `llm/narration`） | 更短更自然 |
| 体验 | 盲评偏好（贴题/记得住/像人/不烦） | 4 维 ≥ 基线 |
| 成本 | p95 延迟、每轮 token/费用、显存 | 阈值内 |

- **在线 A/B**：2 周盲测，按用户/流量分流，人不知系统来源。
- **失效剖析**：剩余错误分类（偏题/记忆漏/风格/事实）。

### 5.4 🚦 Go/No-Go · 交付物 · 工期 · 成本
- **门 P5**：① 原功能不回退；② 偏题率↓≥20pt 且记忆使用率↑；③ 延迟/成本在阈值内；④ **可一键回滚**。

- **算力**：见附录 B（**≈ ¥1000–3000**）。
- **工期**：训练 + 实施 + 观察 约 3–5 周。

## 阶段 6　基于全双工模型的深入拓展（**后续规划**）

> 本阶段**不是当前目标**（阶段 0–5 明确不做全双工），仅作**架构预留与路线图**。
> 好消息：**Qwen3.8-27B 已是原生多模态（文本+视觉）**，视觉输入天然支持。

### 6.1 视觉输入适配（近中期）
- Qwen3.8-27B 原生支持 vision → 直接接入图像/截图理解（如看用户发的图、看桌面）。
- δ-mem 适配：视觉 token 直通、不写入记忆 S；**文本语义摘要**才写入 S（保持 S 紧凑）。

### 6.2 语音输入/输出（中期）
- 参考业界已实现方案：Moshi / Freeze-Omni / ORISE / FLAIR / STITCH（音视频流式、打断 barge-in、语音 latent）。
- 架构预留：把"思考—记忆总线"抽象为**与模态无关的中间层**，语音/视觉只替换输入输出编码器。

### 6.3 架构预留原则
```
[任意模态输入编码器] → [共享认知层: MIRROR 思考循环 + δ-mem 记忆总线] → [任意模态输出]
```
- 新增模态 = 换编码器，**认知层与记忆层不动**。
- 风险：流式/打断会引入时序与延迟约束，需重新设计状态机的并发与抢占。
- 工期：待阶段 5 稳定后再评估（**多模态全双工训练成本远高于本计划**）。
