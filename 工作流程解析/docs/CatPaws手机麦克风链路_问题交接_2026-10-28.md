# 手机麦克风链路 · 问题交接报告（2026-10-28）

> 交接对象：负责 iOS 端（CatCam / CatApps_iOS）或手机链路的工作区
> 现象：手机对着说话，主程序那边**不识别**；关掉电脑麦克风后更完全没有反应
> 本文把「已证实的事实」和「推断」严格分开，每条都带验证方法

---

## 一、结论摘要（TL;DR）

| # | 结论 | 性质 |
|---|---|---|
| 1 | 手机 ↔ 电脑 **HTTP 是通的**（App 状态页三绿，`.cam` 每秒收到手机的请求） | 已证实 |
| 2 | 手机今天 **一个字节的音频都没上传**（`.cam` 三条音频路由全为 0 次） | 已证实 |
| 3 | 手机上跑的是 **CatCam App 的原生相机页**，不是浏览器网页（今天没有手机端的页面加载） | 已证实 |
| 4 | 所以"手机麦克风不被识别" = **上游没有数据**，不是识别、不是声纹、不是 meowid | 已证实（对手机而言） |
| 5 | 但声纹校验确实会丢数据：00:21–00:24 的 12 条识别全被 `unknown` 拦掉（那是**电脑麦克风**的音频） | 已证实 |
| 6 | App 的音频/视频链路走的是**一条从未建立的 WebSocket**（`wss://IP:8443/ws`） | 推断（强证据） |
| 7 | 即便音频接上，`inject` 源现在 `speaker_verify: true` 仍会把手机音频丢掉 | 已证实（机制） |

**一句话**：先修 App 的 WS 连接（或改用浏览器网页），再关掉 `inject` 源的声纹校验并把身份设成 `000001`，三件事都做完手机语音才会通。

```
D:\Virtual Machines\connector\WDA\CatCam\CatCam\CWLive.swift
```

**推断（强证据）**：`configure()` 只被调用一次；如果那一刻配置还没读完（`pcHost` 为空），`guard let host = config.camHost else { return }` 会直接返回，`wsURL` 永远为 nil，11 行的 `if let wsURL` 就永远不执行 → 相机和麦克风都不会连。之后配置就绪也**没有人再调用 configure**，所以这条链路永远不会自己恢复。

## 三、假设清单（按可能性排序，含证伪方法）

### H1（最可能）App 从未建立音频 WS，手机客户端根本没发音频

- 支持：`/api/mic`、`/api/audio/send`、`/api/audio/end` 全为 0；App 日志没有「音频/视频链路已连接」；多点 `netstat` 未抓到手机到 8443 的 ESTABLISHED；源码见 2.4。
- 反对：`.cam` 的 `/ws` 不写日志，无法从日志直接证否；理论上 App 可能用别的通道（未观察到）。
- 验证（5 分钟）：
  1. 手机进 CatCam「相机」页，点**麦克风**球；
  2. 电脑上 `netstat -ano | findstr :8443` —— 只出现 `TIME_WAIT`（HTTP 轮询）没有 `ESTABLISHED`，即确认 H1；
  3. 或给 `.vendor/.cam/ws_hub.py::serve()` 加一行 `print('[ws] connect', ...)`，重开 App 看有没有输出。
- 若成立：按第四节 P0 打补丁重打包。

### H2 App 发了音频，但走了 WS 二进制而服务端没接住

- 支持：`ws_hub` 对未知帧格式的容错未知；`/ws` 无日志。
- 反对：`[inject]` 识别会话已建立但**没有一条识别结果**，若服务端收到了二进制音频，应该至少产生噪声识别（参考电脑麦那 12 条）。
- 验证：给 `ws_hub._on_bin` 加计数日志，或在 `AudioGateway.feed()` 入口打印帧数。

### H3 音频到了但被声纹校验丢弃

- 支持：机制成立（见 2.3 电脑麦那 12 条被丢）。
- 反对：**inject 会话没有产生任何"识别到最终文本"**，声纹丢弃发生在识别之后，没有识别结果说明音频没进来。
- 验证：等 H1 修好、有音频之后看这条；届时把 `inject.speaker_verify` 关掉即可。

### H4 音频到了但身份解析失败（meowid 问题）

- 支持：`manager.py:190-198` 在 `meowid_of_msg()` 拿不到身份时会 warning `没有对应身份，已忽略`。
- 反对：今天日志里**没有**这条 warning，连识别都没发生。
- 验证：同样要等有音频；届时确认日志是否出现 `✅ 跳过声纹验证，使用配置身份: 000001`。

### H5 手机端 mic 权限/静音/未开麦

- 支持：截图里相机页的**麦克风球是灰色（未开）**；页面上的相机球也是关的。
- 验证：手机点一下麦克风球，看图标是否变粉、iOS 顶部是否出现绿色小点。
- 若成立：这是最表层原因，但仍然要先满足 H1（WS 成立）才能上传。

### H6 服务端多实例/旧实例

- 现状：8443 只有一个监听（pid 34120），1800 一个（pid 33128），暂未见重复实例。
- 验证：`netstat -ano | findstr "LISTENING" | findstr ":8443 :1800"`，出现两个不同 pid 即中招。

## 四、修复清单（按优先级）

**P0 · App 的 WS 连接（不做这条，相机和麦克风都不会工作）**

`CatCam/CWLive.swift` → `configure(_:)`：

```swift
if key != configuredKey {                    // 只有地址/协议变化才重算 URL
    configuredKey = key
    base = URL(string: "\(scheme)://\(host):\(port)")
    wsURL = URL(string: "\(wsScheme)://\(host):\(port)/ws")
    ...
}
if started, let wsURL {                      // 不管 key 变没变，没在跑就补连
    if !videoLink.isOpen { videoLink.start(url: wsURL) }
    if !audioLink.isOpen { audioLink.start(url: wsURL) }
}
logSink?("推流目标：\(wsURL?.absoluteString ?? "（空，检查 PC 地址）")")
```

`CatCam/CWCamNativeView.swift` → View 上补：

```swift
.onChange(of: store.config) { _ in live.configure(store.config) }
```

`CWLive.start()` 里把 `if let wsURL` 的 else 分支写上日志，避免以后再「静默不连」。

**P1 · 关掉手机源的声纹校验**

```yaml
audio:
  sources:
    inject:
      enabled: true
      speaker_verify: false      # ← 手机声纹与 'YGZ醒脑片' 不匹配，开着必定被丢
      username: '000001'         # ← 身份兜底（页面没带身份时用）
```

> ⚠️ 这个文件会被 GUI 的音频面板保存/热重载覆盖（本次就被改回去过一次）。正确做法：**先停主程序 → 改文件 → 再启动**，或直接在 GUI 音频面板里改。

**P2 · 手机端身份必须是编号**

`.vendor/.cam/static/js/main.js`：

```js
const PHONE_UID_RE = /^(\d{6}|temp-\d{6})$/;   // 只接受六位编号
return saved 命中 ? saved : '手机用户';         // 没设过就发"手机用户"（不是 meowid）
```

- 浏览器页：点左上角「未设置」→ 填 `000001`；
- App：设置里 MeowID 填 `000001`（截图里已经是了）。

**P3 · 验证成功的三个标志（缺一不可）**

```
1) netstat 出现 手机(.84) → 8443 的 ESTABLISHED
2) .cam 日志出现 /api/audio/send（浏览器页）或主日志出现 [inject] 识别到最终文本（App WS）
3) 主日志出现 ✅ 跳过声纹验证，使用配置身份: 000001
```

## 七、还没定论的点（交接方接手前请先确认）

1. 手机 .84 到 .159 的 **ICMP 不通但 HTTP 通** —— 是否符合你们网络环境（iOS 热点/AP 隔离常见），以便判断"ping 不通"能否作为判据；
2. App 的 `camHTTPS` 开关与 .cam 服务端**只有 HTTPS**，把开关关掉（走 8445 明文）是否也能工作（`.cam` 8445 是明文 HTTP，`/ws` 也由同一 handler 处理，理论上可行）；
3. 若采用浏览器网页方案，`/api/audio/send` 是现成的、今天 0 次只是因为**手机没打开网页**——这条最省事，建议先验证它。
