# 导演模块 · 真实提示词走查 / 模拟演出

> 目的：让你在不启动模型的情况下，看到导演模块**实际会发出去的提示词**，以及按这套提示词走一遍戏是什么效果。
> 说明：
> - **【真实】**：由仓库里的真实代码渲染/读取，原样粘贴（角色卡、心理样例、短记忆样例是输入数据）。
> - **【模拟】**：模型侧的输出（工具调用参数、台词），由我按真实提示词手动扮演，**没有调用任何模型**。
> - 样例心理、样例对话、样例视频都是构造的；提示词模板、注入位置、块格式、工具 schema 全部是真的。
> - 角色卡当前性格是「温柔」，所以台词按温柔喵呜的写法（不说短句、不命令、不骂人、平常不带「喵」、不说「睡」「我认」「我不催你」）。

### 1.1 判官提示词（【真实】`func/llm_active/director/prompts/judge_prompt.txt` + 心理）

system：

```text
你是喵利呜西斯。你在心里判断一件事：主人现在是不是没意思了、聊天是不是明确断了。
只做判断，不写回复。

【判 true 要有证据】（bored / no_topic）
- 他的回复越来越短、只是「嗯」「哦」「随便」「好」这类，没有新东西，也不问你；
- 话题已经断了：他没接你的话，或者你们在重复同样的东西；
- 他明确表现出没事干、好无聊。

- 他在讲自己的事、在问你问题、在认真回你；
```

```text
【任务指令】
你是喵利呜西斯。现在轮到你自己找话说，不是等主人给话题。
你要先想清楚「这一场要怎么演」，再开口。下面是硬规矩。

【什么时候该开始】（start=true 只在这些时候）
- 主人连着敷衍（「嗯」「哦」「随便」「不知道」），明显没意思了；
- 聊天明确断了：他接不下去，或者你们已经在没话找话；
- 你想主动问「最近有什么好玩的视频」这类由头。

【什么时候绝对不要开始】（start=false）
- 主人有明确话题、在讲一件事、在问你问题；
- 他在忙正事（做题、工作、打游戏）而且刚说过；
- 你们正聊得起劲，还在来回接话。

【清单怎么写】
- 写行为与思路，不写台词：这一步要干什么、猜他会怎么接、他不接时怎么拉回来。
- 每一步只做一件小事。绝不允许把后面几步的内容一次说完，这是硬规矩。
- **素材是视频时，至少一步要写清楚**：我要讲视频里的哪个具体画面 / 哪句台词 / 我为什么在意它。
  视频是这一场要分享的内容，不只是个引子；不写具体，执行时你就只能泛泛地聊「一个东西」。
- 参考过程（不是模板）：引起注意 → 勾起兴趣 → 慢慢引导 → 设置转折 → 揭晓答案。
- 可用招法（不局限）：让他猜东西、猜你下一句、关心地问他的情况、考他记不记得、

- 步数由你定，够把这一场演完就行，不设上限。

【红线】
- 禁止冷笑话。
- 禁止写死要说的台词：可以写一句引导方向，但不能是整句成品。
- 视频可以讲，但不许照着简介复述、不许一次讲完：讲具体的某一处就够。
- 不许一上来就把答案、转折、揭晓全抖出来。

【怎么用素材】
- 素材是引子，不是任务。可以用它开场，但不要照着念。
- 需要找旧事当由头时，可以调用文件工具翻 character/memory 里的记忆：
  list_files / read_file / keyword_locate / slice_file / jieba_segment。

【输出】
必须调用 director_plan 工具；不要输出解释性正文。
```

````markdown
# 当前对话走向（必须照做）

（由头只是引子，不是台词：不许照着复述，也不许一次讲完）
当前这一步（只说这个）：
  [>] 1 先只说我在看一个东西，留半句不说破
      招法：卖关子；猜他会：他会问「什么东西」；他不这样就把话拉回来：他要是只回个「哦」，就笑他一嗓子再问回去

  [ ] 2 让他猜那是什么东西（招法：让他猜）
  [ ] 3 他说出「你到底在看什么」之后再揭晓，揭完就收住不解释（招法：揭晓）
  [ ] 4 把话题拉回我这边，让他说一句自己的看法（招法：把话头递给他）

  · 不许冷笑话
````

## 2. 第一幕的后续：主人一直没回 → 失望 → 重写

计时到下一轮（演示里把 `cold_time` 设短；线上默认 3600 秒），主人一条消息都没有 → `silent_rounds=1`。

本轮提示词：主动回复提示词 + 导演块 + （【真实】`_turn_hint("idle_disappointed")`）：

```text
# 这一轮只做这些
他一直没回你。你有点失望（别抱怨、别卑微），把[>]这一步换个钩子再试一次；要改这一步的做法就填 adjust，别把刚才的话重讲一遍。说完必须调用 director_step 交回进度。
```

## 5. 素材是怎么传递的（视频 / 回忆）

分四个时间点看：

**① 抽素材（规划前）** — `DirectorMaterial.pick()` → `AutoRandomTopic.pick()`，和原来 origin 完全同一个池子：
- 话题池：`MeowSummaryTool.TOPICS` 的 5 个话题（日常 / 爱好 / 哲思 / 闲聊 / 情感）+ `character/abstract_memory/tags/tags.json` 里随机一个标签；
- 视频池：`.temp/web_browse_cache/*.json`（后台 `AutoBrowseCore` 抓取 → LLM 过滤 → 抽帧 → 视觉概括 → 落盘的一条小结）；
- 池子 = 1 个话题 + 每个缓存视频各 1 个 ⇒ 视频被抽中的概率 = 视频数 /（视频数 + 1）。

**② 给规划器（唯一一次完整素材）** — `material.describe()` 渲染成 `【素材·视频】` / `【素材·回忆】` 段，放进 planner 的 **user 消息**：
- 视频：标题 / 时长 / UP主 / 内容（视觉概括的 `content`）/ 话题 / 标签 + 「由头不是任务：不许复述、不许说好的我来分享」；
- 回忆：话题 + 标签 + 最近说话人档案（`.temp/*_record.txt` 的修改时间倒序）+ 按话题/标签筛出的记忆摘要（`character/abstract_memory`）。
模型据此写 steps——**素材只在这里完整出现一次**。

**③ 留存与执行（每一轮）** — `_material_meta()` 只把 `{type, title, topic, tag, path, brief}` 写进计划的 `material`：
- `brief`：视频 = `标题｜content`（截 400 字；视觉概括本身限 300 字，基本就是全文）；回忆 = `话题（标签）`；
- `brief` 会被渲染进「当前对话走向」块的 `由头：…` 一行，**每轮都带**，并附一句「由头只是引子，不是台词：不许照着复述，也不许一次讲完」；
- 另外主动回复提示词会把 `material.topic` 当 `topic_override` 传给 `build_active`，用于记忆摘要检索（和 origin 的视频分支一致）。

**④ 消费** — 计划真的开始（`start=true` 且步骤有效）后，视频 json 由 `AutoBrowseStore.move_to_collect()` 从 `.temp/web_browse_cache` 移到 `character/shared_videos`（和原来 origin 一样），并且**计划里的 `material.path` 同步改成收藏路径**（以后要做回看/引用时找得到）；规划失败 / 不开始则不动。回忆素材没有消费动作。

一句话：**完整素材只喂给规划器一次；执行阶段靠计划里的 `brief`（每轮由头）+ steps + 对话本身，不重复喂全文。** 不每轮喂全文是刻意的：视频小结 150~200 字，每轮塞进提示词会诱导它照着念；`brief` 只保证它记得「这一场在聊什么」，细节由它自己开口那句和后续对话承接。

## 6. 这份演示是怎么生成的

- 判官/规划器/提示词的文本：用仓库真实代码渲染（`DirectorJudge._system/_user`、`DirectorPlanner._system/_user`、`SystemPromptBridge.get_active_prompt/get_system_prompt`、`render_director_block`），只把日志写盘、身份表锁、心理线程、知识库这些外围打桩，**没有调用任何模型**。

## 7. 实测记录（真模型，2026-10-29）

用例：缓存里真实视频《“这一刻，神性已成！！！”》（中国奇谭混剪，`content` 179 字）；样例对话为连续敷衍；真调 deepseek 配置的模型。为隔离副作用，测试里只读了真实素材/提示词/角色卡，日志、短记忆、身份表、心理线程、知识库、情绪更新都做了打桩，**没有向 `.temp` / `character` 写任何东西**。

### 测试 A（修改前）

- 判官：命中（引用原话「没事」「嗯」「好无聊」）。
- 规划：4 步，但全是 meta（“把他从发呆里勾出来”“抛一个我想不明白的小念头”“把话头递给他”），**没有一步写具体画面/台词**。
- 每轮提示词：**5/5 都含 179 字全文**，`brief` 没截断 → 记忆/可达性没问题。
- 回复：前 3 轮都在聊“你闷不闷”，视频内容一次没提；第 4 轮直接问“视频讲了什么”，只答“国风混剪、《中国奇谭》的二创”（标题级），没展开具体画面。
- 折叠 tool：4 轮只推进 1 次（卡在第 2 步）。

结论：**内容确实每轮都在提示词里，但规划没安排“讲具体哪一处”，执行就只按步骤走，概括没被用上。**

### 修改

1. `planner_prompt.txt`：素材是视频时，至少一步写清“哪个具体画面 / 哪句台词 / 我为什么在意”；红线从“视频只是由头”改成“视频可以讲，但不许照简介复述、不许一次讲完，讲具体某一处就够”。
2. `director_step` 的 `completed` 语义改为“说出口就算完成，他没接不算没完成（用 adjust / if_not 决定下一步）”。
3. 导演块 + reply 的 turn hint 同步加：“这一步说出口就算完成”“要讲由头就讲具体那一处（画面/台词），别空着”。

### 测试 C（修改后，跑完整场）

同一条视频、同一套提示词，让用户用探询式回复（“什么东西 / 然后呢 / 所以呢 / 还有呢”）把戏走完：

- 规划（真模型）4 步：
  1. 把话头抢过来，先不追问他在干嘛，卖关子说“刚被一个画面绊住了”；
  2. **只讲一个具体画面：那个小妖怪一边掉眼泪一边说“以后少吃一点”**；
  3. 把话头递给他，问他觉得这种老老实实认命的人算不算有种；
  4. **再翻到另一个画面：有人捏着花说“成仙指日可待”，脚下全是战火**。
- 开场/第 1 轮：*“你先别急，我看完心里有点堵得慌，就想找个人说说”*（只钩住，不抛内容）。
- 第 2 轮：*“有个小妖怪，一边掉眼泪一边说『以后少吃一点』，我就卡在这句上了”* → 用到了具体台词。
- 第 3 轮：*“那么老实、那么认命……你说这种人到底算不算有种”* → 把话头递回去。
- 第 4 轮：*“还有个画面更让我想不通，有个人手里捏着花，说成仙指日可待，可他脚底下全是战火”* → 用到了第二个具体画面。
- 折叠 tool：第 3 轮打标第 1 步，第 4 轮把 2/3/4 一起打标 → **全部完成 → clear**（`active=False`）。
- 每轮提示词：**5/5 都含 179 字完整概括**。

这一场里，视频概括的两处关键内容（小妖怪的“以后少吃一点”、鹅鹅鹅的“成仙/战火”）都被用上了，而且不是一口气倒完：前两轮只钩、第三轮递话头、第四轮才翻第二个画面。测完就 clear，恢复走主链路。

仍有一点小毛病：开场/第 1 轮没打标（`turns` 还是 0），第 3 轮才补上，第 4 轮一次打标 2/3/4——进度打标会慢一拍，靠 `stall_turns` 兜底；不影响内容使用。
