# Part A — 框架（先做，无训练）

## A.1 四条设计原则
1. **解耦**：思考走独立调用，思考文本**永不进 TTS**（对比现状：现在依赖基座 `<think>` 标签，单轮内、不可持久）。
2. **持久**：思考是**常驻后台进程**，不是"每轮现算"。回复结束 → 思考**继续**（你的 3.1）。
3. **焦点**：Talker 每轮只拿一个 `focus`，**强约束只回应它**（对症"求全/偏题"）。
4. **记忆走注意力**：记忆不塞 prompt，而是进 δ-mem 状态（Part B 接上）。

## A.2 状态机（核心）

```
         ┌────────────────────────────────────────────────┐
         │                                                │
   [IDLE] ──用户消息到达──► [TALK] ──TALK 结束──► [THINK] ──┘
     ▲                        │  │                 │
     │                        │  └─并行走 [THINK]   │ 空闲 tick / 新记忆
     │                        │                    ▼
     └────── 无输入且思考沉淀完成 ──────────── [THINK] 持续/续跑
```

- **TALK**（前台）：读 `ThinkState.focus` + 最近 history + **少量**高相关记忆 → 流式输出**短句**。
- **THINK**（后台线程）：与 TALK **并行启动**；TALK 结束后**不停止**，继续产出 `plan_next`（下一轮预案）。
- **下一轮**：新的用户消息到达时，Talker 直接用上一轮沉淀的 `focus/plan_next` 作为起点（跨轮延续），同时把新消息并入思考。
- **salience 门控**：琐碎轮（如"嗯""哈哈"）跳过思考，省成本。

## A.3 数据结构：`ThinkState`（每用户一份，落盘）

```json
{
  "user_id": "YGZ醒脑片",
  "focus": "一句话：本轮只该聊什么",
  "thinking": "持续思考的滚动摘要（内部，禁止复述）",
  "plan_next": ["下一轮可能想说的点", "想问的问题"],
  "open_threads": [
    {"topic": "学唱《星降る海》", "status": "用户催过2次", "next": "下次可主动提"}
  ],
  "salience": 0.0,
  "updated_at": "2026-09-17T21:00:00"
}
```
- 路径：`.temp/think_state_<user>.json`（每用户一份 —— **与 Part B2 的每用户矩阵同键**）。
- 复用你现有的 `.temp/*.json` + 状态桥接单例模式（`TurtleSoupStateBridge`、`LLMTimerBridge` 同款）。

## A.4 思考循环（后台线程）

```
on 用户消息 / on TALK结束 / 空闲 tick:
  1. 读 history(短期) + ThinkState + 去年记忆(B1/B2 提供的少量高相关条目)
  2. 问自己（独立调用，输出严格 JSON）：
     - 用户真正在意什么？
     - 当前焦点应设为哪一句？
     - 哪些点这轮不该说、留到下一轮？
     - 哪些未完成话题要记着？
  3. 写回 ThinkState（focus / plan_next / open_threads / thinking）
  4. 若 TALK 已结束 → 立即再跑一轮，产出"下一轮预案"
```
- **每轮重构，不累积**（MIRROR 的核心教训）：`thinking` 每轮重写，禁止无限追加，否则又变成"信息大杂烩"。
- 上限：`thinking ≤ 200 字`，`plan_next ≤ 3 条`，`focus` 必须 1 句。

## A.5 Talker 契约（对症问题1）

Talker 的 system 结构改为**分区**：
```
# 你此刻的内心（仅供思考，禁止复述）
{thinking}

# 本轮焦点（必须遵守）
只回应：{focus}

# 行为约束
- 只输出与焦点相关的一句，其余留到之后
- 不总结、不铺陈、不复述内心
- 直接说，像平时聊天

# 记忆（少量）
{高相关记忆 3~6 条，由 B1/B2 提供}
```
- **关键否定式约束**是当前最缺的（前置词只说"回一句话"，没禁止覆盖全部素材）。
- 记忆注入量从**最多 20 条降到 6 条以内**，且由 δ-mem 重排（见 B1）。

## A.6 与现有代码的挂接点（不改架构，只加模块）
- `func/llm/llm_core.py :: _ai_response`
  - 开头：读 `ThinkState` → 注入 system 分区
  - 末尾：起后台 `thinker` 线程（复用现有 `Thread(...).start()` 模式）
- **可直接升级 `func/llm_active/inherit/inherit_core.py`**：它已是"跨轮延续话题"的雏形，改成"延续思考"最省。
- `func/llm/output.py`：`split_limit=6` 的切句逻辑天然适配"短句流"，无需改。
- 新增：`func/thinker/`（`think_state.py` / `think_loop.py` / `think_prompt.py`）。

## A.7 Part A 验收（无需训练）
- 偏题率下降：焦点命中率 ≥ 基线 +20pt（自建 eval，见 B5）。
- 回复平均句数下降、单句更短。
- 跨轮延续可见：`plan_next` 被下一轮真实引用。
- 稳定性：连续 200 轮不阻塞、不丢状态。

# Part B — 模型训练

> Part B 只训**旁路参数**，基座冻结（δ-mem 论文与 CLS 论文的共同结论）。你现有的
> **tag 打分 / evidence 衰减 / 摘要条目**全部保留，作为记忆的**写内容**与**门控键**。

## B1. 注意力机制：δ-mem（跨轮在线记忆）

### B1.1 机制（照 δ-mem 论文，逐式）
```
# 每层、每位置
qm, km = l2norm(tanh(Wq x)), l2norm(tanh(Wk x))
vm     = Wv x
beta   = sigmoid(Wb x + b);  lam = 1 - beta

r      = S_prev @ qm                       # 读
dq, do = Wdq @ r, Wdo @ r                  # 低秩修正
q'     = q + (alpha/r_dim) * dq            # 注入 query 分支
y'     = Attn(q', K, V) + (alpha/r_dim)*do # 注入 output 分支
S      = Diag(lam) @ S_prev + Diag(beta) @ outer(vm - S_prev @ km, km)  # delta 写
```
- 只训：`Wq^m, Wk^m, Wv^m, Wb, Wdq, Wdo, S_0`。基座冻结。
- 默认：`r=8, alpha=16`，**q/o 分支**，**全部层**。

### B1.2 写什么（直接复用你的现有记忆资产）
- **写单元（`C`）** = 该用户的记忆条目序列：`character/abstract_memory/meow-*.json` 按 `time` 排序。
  - 一条 event + tags + topics 拼成一段文本，**按消息段写一次（SSW）**，抗噪。
- **查询（`Q`）** = 本轮用户消息。
- **目标（`Y`）** = 本轮 AI 回复（`Output` 清洗后的文本）。
- **用户档案**（`*_latest.json`）→ 作为 `S_0` 的初始化，或作为门控信号（B2）。

### B1.3 训练
```
loss  = CE(Y | Q, S_C)        # 只喂 Q，不回放 C（逼记忆进状态）
loss += λ_usage * 焦点一致性   # 可选：回复是否落在 focus 上（用 eval 打分器做弱监督）
```
- 超参：`lr=2e-4`，cosine + warmup 0.1，有效 batch 32，bf16，1 epoch。
- 数据：从 `character/memory/*.txt` 切窗构造 `(C, Q, Y)`，目标 1w~5w 条。
- 算力：单卡 24G（Qwen3-4B + ZeRO-2/LoRA-style 只训旁路）。

### B1.4 必做消融（论文已给方向）
| 变量 | 取值 | 预期 |
|---|---|---|
| 插入层 | all / middle / front / back | all 最优，middle 次之 |
| 分支 | q / o / qo / qkvo | qo 最佳性价比 |
| 写粒度 | TSW / SSW / MSW | 对话选 SSW；干扰大时 MSW |
| r | 8 / 16 / 32 / 64 / **128** | 128 容量大但需门控（见 B2） |

### B1.5 验收
- **no-context 测试**（δ-mem 论文核心指标）：把历史原文移除，只留 `S_C`，看能否答对记忆问题。
- 记忆召回率、焦点命中率上升；闲聊自然度不退化。

## B2. 每用户 128×128 矩阵

> 你的原话："每个用户可以生成一个 128×128 的矩阵，用于回复。"
> 落地有两条**已验证**的路径，**推荐组合**，避免单个无门控大矩阵的干扰问题。

### 路径 1（推荐主用）：per-user δ-mem 状态
- 把 B1 的共享在线状态改成**每用户一份**：`S_u ∈ R^{r×r}`，取 `r=128` → 正好 `128×128`（16,384 参数/层/用户）。
- 用户在"思考循环"里读/写自己的状态；Talker 生成时用该状态产生注意力修正。
- **抗干扰**：用 **MSW**（N 个子状态，如 4 个 `64×64`），按主题分槽（日常/爱好/情感/哲思，正好复用你的 `topics`）。

### 路径 2（推荐补充）：CLS 门控 LoRA（每用户/每主题一个残差矩阵）
- 位置：**MLP down-projection，中间层**（Qwen3-8B → 第 15/36 层；4B 按比例取中段）。
- 形态：**masked rank-2 LoRA**，随机 `m` 个输入/输出神经元；约 **2~3 参数/token**。
- 门控：`g_i = δ(i, argmax_j cos(e_j, e_cue))`，`e` 用你已有的 **bge-m3 端口**（`database/store/port`）编码用户/主题。
- 输出：`Wx + Σ g_i B_i A_i x`。
- 优点：**多用户互不污染**（赢者通吃）、**可增量写入**（来一条新记忆就训一个小 adapter）、参数极省。

**映射建议**
| 你的说法 | 实现 |
|---|---|
| 每用户 128×128 矩阵 | 路径 1：`S_u ∈ R^{128×128}`（或 MSW 4×`64×64`） |
| 结合当前用户档案 | 档案 → `S_0` 初始化 + 门控键 |
| 保留 tag 打分与摘要条目 | 直接作为 δ-mem 写内容 / LoRA 训练样本 |
| 说话内容微调 | 路径 2 的 adapter 学"该用户怎么说"（口吻/称呼/禁忌） |
