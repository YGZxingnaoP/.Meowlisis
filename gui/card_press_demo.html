主界面用的就是下面 full（组合）这一套，参数与本页一致（3D 幅度 20°、下沉 3px、90ms 按下 / 420ms 弹簧回弹）。 想改手感就改本页的 MAX_TILT / HOVER_TILT 与 .card-press 的过渡，再同步到 js/press.js 和 css/cards.css。 笔/触屏设备会真的读 pointer.pressure 决定下沉深度，鼠标固定 0.5。

四种模式在做什么

模式按下去松手
sink 下沉 90ms 内下沉 3px + 缩到 0.965，阴影收紧、变短（卡片贴近桌面） 420ms 弹簧回弹，过冲到 1.008 再落回（用 cubic-bezier(.22,1.36,.36,1) 近似）
tilt 3D 跟随 最多 20° 的 rotateX/rotateY 跟着指针，镜面高光跟着走；按下再往屏幕里推 8px 指针离开 → 角度归零；松手 → 弹回并带一点光晕收束
spot 触点涟漪 按下那一点亮起白色光斑，同时向外炸一圈涟漪（62% 时最亮） 光斑随压力值淡出
full 组合（推荐） 3D 跟随 + 下沉 + 触点光斑 + 镜面高光 + 外发光 弹簧回弹，涟漪一次性散开

接入方式（主界面已经是这样做的）

1. 压感挂在 .card-press，绝不是 .slot。
结构：.slot > .card（只翻牌）> .card-press（只管下沉/倾斜）> .face.front + .face.back。 .slot 的 transform 是轨道每帧重写的（orbit/rotation.js 的 _placeAt）， 写上去会被下一帧吞掉，还会重演"半径在变"的老 bug。分两层也让翻牌的 0.5s 弹簧和压感的 90ms 下沉各走各的时序。
2. 事件用 Pointer Events + setPointerCapture。
pointerdown 里 capture，pointerup / pointercancel / lostpointercapture 里复位； 另外指针一移超过 4px 就当场复位 —— 那说明用户在搓轨道，不是按卡片（js/press.js 的 DRAG_TOLERANCE）。
3. 只写 CSS 变量，并且合帧。
--press / --tx / --ty / --sx / --sy 五个变量 + .pressing 一个类， 写入统一丢进 requestAnimationFrame；不碰 width/height/top/left，就不会有重排。

落到主界面上的清单（已实现）

  • js/press.js：PressFx.bind(el) 由 Orbit._buildCard 逐张调用，外环 / 启动 / 工具箱 / 子卡全覆盖；closeAll 里 PressFx.releaseAll() 兜底复位。
  • css/cards.css 的 .card-press / .card-glare / .card-spot / .card-ring 四块样式，参数和本页一致（3D 幅度 20°）。
  • 触屏用 navigator.vibrate(8) 做"真的"触感；桌面端靠弹簧曲线表达。
  • prefers-reduced-motion: reduce 下退化成"只有下沉、没有回弹和涟漪"（本页可切系统设置验证）。
  • 拖动轨道、点空白收起、打开面板都会复位，不会留一张卡卡在半按状态。
