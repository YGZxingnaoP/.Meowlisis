## 1. 论文机制：只抄公式，别抄错

δ-mem 的全部内容就是下面五组式子。**backbone 全程冻结**，只训 θ（约 0.1% 参数）。

### 1.1 记忆投影（式 4、5）

```
qᵐ = L2norm(tanh(W_q x))      kᵐ = L2norm(tanh(W_k x))      vᵐ = W_v x        (∈ R^r)
β  = σ(W_β x + b)             λ  = 1 − β                                     (∈ R^r)
```

`x` 是该层 attention 的输入隐状态（Qwen3 里是 `input_layernorm` 之后那一份，每元素 rms≈1）。
**q/k 归一化、v 不归一化**，β/λ 逐维 —— 这三点是稳定性的来源，别省。

### 1.2 读（式 6）

```
r_t = S_{t−1} qᵐ_t          # 定长状态，代价与历史长度无关
```

### 1.3 用读向量驾驭 attention（式 7–9）

```
Δq = W_q^Δ r_t      Δo = W_o^Δ r_t
q̃  = q0 + α Δq        ← q0 是 q_norm 之后、RoPE **之前**的 query
a  = Attn(q̃, K≤t, V≤t)
ỹ  = a + α Δo         ← 加在 attention 输出上，即 o_proj 之前
```
论文只用 q + o 两个分支（§5.2 的头消融：qo 47.97 已接近 qkvo 48.05，但参数省一半）。

### 1.4 写（式 10–12）

```
S_t = Diag(λ_t) S_{t−1} + Diag(β_t) (vᵐ_t − S_{t−1} kᵐ_t) (kᵐ_t)ᵀ
```

三个项分别是「保留」「擦掉旧预测沿当前 key 的分量」「写入新值」。逐行展开就是式 12：
**每个记忆维度 i 独立控制保留多少、写多强**。

一个容易抄错的地方（我第一版单测就写错了）：式 (2) 的**无门**形式 `S + β(v−Sk)kᵀ`
等价于对 `½‖S k − v‖²` 做 lr=β 的 SGD；但式 (3) 加了 `λ=1−β` 的门以后，它等于
"SGD 一步 + 向 0 收缩 β 倍"，β=1 时是**纯重写**而不是在旧状态上做 SGD。
`test_math.py` 的 [2]/[2'] 两条就是钉这个区别的。

### 1.5 写入粒度（§3.5）与训练目标（§3.6）

| 粒度 | 做法 | 代价 |
|---|---|---|
| TSW | 每 token 写一次 | 最细，但吃格式符/重复表达 |
| **SSW** | 每段取隐状态均值写一次（式 14） | 抗噪，论文在 8B 上最好 |
| MSW | N 个并行子状态，读出来 concat | 小模型收益最大（SmolLM3-3B: 26.08→36.96） |

训练：`L = −Σ log p(y_j | Q, y_<j, S_C)` —— **context 写进状态后从输入里删掉**，
backbone 只看到 Q + Y。这是整个方法能成立的关键，也是数据必须重做的原因（见 §2.1）。

论文超参：r=8、α=16、qo 分支、**全层**（§5.3）、MSW 的 N=4、QASPER 最短 2219 条子集、
1 epoch、backbone 输入 512、写记忆预算 8192 token、lr 2e-4 cosine + 0.1 warmup。

## 2. 要准备什么数据

### 2.1 为什么闲聊数据没用

训练样本必须是 **(context, query, response)**，且 **response 只有在读过 context 时才写得出来**。
原因是权重只从「状态里的信息是否被用上」这条路径上更新：

- 如果 response 不依赖 context，模型最省力的解就是**把 αΔq 压到 0**，loss 照样降，记忆通路学不到东西；
- 论文 §5.1 专门做过「把 context 删掉、只留状态」的对照（HotpotQA EM 0.08 → 6.48），
  说明状态里确实存了东西 —— 但那是**用强依赖 context 的 QA 数据**训出来的。

所以：**你现在的闲聊/情绪/唱歌数据一条都不能直接拿来训 δ-mem**，只能当"风格锚点"少量掺入。

### 2.2 你手上有什么（盘点）

| 路径 | 内容 | 量 | 能产出的样本 |
|---|---|---|---|
| `character/abstract_memory/*.json` | 记忆事件（event + tags + topics + importance） | **439 条**（4 个文件） | 主力：每条 → 1~3 条问答对 |
| `character/userinfo/*.json` | 用户档案（昵称/关系/偏好） | 27 个文件 | 偏好/人称类问答 |
| `.temp/*_record.txt` | 短时对话轮次（GBK） | 9 个文件 / 5 段 | 语气与格式，几十条 |
| `logs/log_*.txt` | 完整对话日志（含 prompt 与回复） | 12 个文件 / ~10MB | 可挖真实回复，但需要清洗 |
| `.vendor/.DataBase/raw_seed/*` | 网页知识（mcmod/萌娘/3dmgame…） | ~数十个 json | 事实型长文本 context（可选） |

**结论：真实可用 ~440 条事件，离 5k~20k 差两个数量级 → 必须合成。**

### 2.3 合成流水线（`labs/dmem/build_data.py`，已可跑）

```
abstract_memory 439 条事件
    │
    ├─[模板模式] 用 tag 套问题模板，答案=事件原文         ← 零成本，450 条/秒
    │            缺点：句式单一，容易训成"复述机"
    │
    └─[教师模型] config.yml 里已有的 deepseek 端点，
                 每批 6 条事件让教师写 1 个"只读记忆才能答"的问答对
                 （answer ≤ 40 字、口语提问、不足以回答就输出 null）  ← 推荐
    │
    ├─ context 组装：目标事件 + 23 条干扰事件，打散后拼成 1000 字左右，
    │                段边界一并写出来（SSW 的 chunk 边界用它）
    │
    ├─ 负样本（10%）：context 照给，问句却与记忆无关（"今天心情怎么样"），
    │                答案应来自角色卡 → 防止模型对所有输入都去"翻记忆"
    │
    └─ 对话样本（少量）：record 的真实轮次，context=前几轮，response=最后一轮
```

实测：439 条事件 → 445 条样本（模板模式）。

### 2.4 配比与规模建议

| 类别 | 占比 | 条数（目标 5k） | 作用 |
|---|---|---|---|
| 单跳事实（事件→答案） | 50% | 2500 | 记忆读写主通路 |
| 多跳（两条事件组合） | 20% | 1000 | 逼状态做联想而非字面匹配 |
| 时间/顺序（"上周三说的"） | 10% | 500 | 补时间感知（配合 calendar 提示词） |
| 偏好/人称（userinfo） | 10% | 500 | 和 abmem/user_memory 对齐 |
| 记忆里没有（答"没聊过"） | 10% | 500 | 抑制编造，这条最容易被忽略 |

- **规模**：r=64 的可训参数约 14.7M，5k 条会明显过拟合；**建议 ≥10k**，20k 更稳。
  r=8 的论文配置用 2.2k 条就够（因为参数只有 4.87M）。
- **长度**：context 512~2048 token（写记忆预算）；query+response ≤ 256 token
  （和 `gen.talk_max_tokens: 256` 对齐）。
- **切分**：按事件（不是按问答对）切 train/valid，避免同一事件泄漏到两边。

### 2.5 评测：必须做"抽掉 context"的对照

论文 §5.1 的做法直接照抄：

1. **with-state**：写状态 → 只喂 query → 看 response 的 NLL 或 EM；
2. **no-context**：不写状态 → 同样只喂 query → 同上；
3. 两者差值就是"状态里到底有没有信息"。**差值 ≈ 0 说明训练白跑**（这次 2 步的结果：6.394 → 6.256，差值 0.14 已可见）。

再加一层外部对齐（可选）：HotpotQA/LoCoMo 各取 200 条子集，和论文的 1.20×/1.31× 对照。

### 2.6 明确不要的数据

长期情绪/好感度（`cat_values`、`affinity`）、唱歌情感、弹幕互动、绘画 prompt ——
这些是"当前状态"不是"历史记忆"，塞进 state 只会污染。它们继续走提示词。

### 3.2 三个必须知道的实现决策

**① Δq 怎么注入 —— 借 RoPE 的线性性**

`q0` 在 `q_norm` 之后、RoPE 之前，这个位置在 `Qwen3Attention.forward` 内部，module hook 改不到。
但 RoPE 对 query 是线性的：

```
rope(q0 + αΔq) = rope(q0) + rope(αΔq)
```

attention 接口拿到的已经是 `rope(q0)`，所以把 `rope(αΔq)` 加上去就**等价于**在 pre-RoPE 处相加，
一行都不用改 transformers。cos/sin 由 attention 的 `forward_pre_hook` 从 `position_embeddings` 取。
自检误差 1.19e-07。

**② 写入阶段关掉 steering（`write_steering=False`）**

论文的写入循环里，`x_t` 会受前面读出的 memory 影响，严格实现要**逐段前向 T 次**。
这里改成：backbone 单趟（分段窗口 + KV cache）采完 hidden，再离线跑 chunk 递推。
代价是丢掉"写入路径的自我一致性"，收益是**一次前向写完整段记忆**。
训练与推理都用同一个约定，所以二者一致。

**③ 生成期间状态冻结**

论文 §3.2 是"先读后写"，生成时也在写。这里只在写记忆那一步更新。
好处是 decode 每步没有递推依赖 → **CUDA Graph / batch=2 双流都不受影响**（对 MeowLLM 是硬需求）。

### 3.3b 每用户一个矩阵（mem0 的对应关系）

| mem0 | δ-mem |
|---|---|
| `user_id` | `owner`（uid） |
| 一条 memory 文本 | 往状态里写一次（`/dmem/write`） |
| 向量库文件 | `<state_dir>/<owner>.pt`（r=64 时 **224KB/人**，28 层 × 64×64 bf16） |
| `search(query)` | 不用检索：生成时状态自动参与 attention |
| `delete_all(user_id)` | `/dmem/forget` |

参数只有一份（14.68M，进程内共享），状态按 owner 切；显存里按 LRU 留最近
`max_cached_owners` 个（默认 8），其余在磁盘上。实测 ownerA / ownerB 同一句提问，

### 3.4 三个实测踩到的坑（写在这里省得再踩一次）

1. **`nn.Module.__setattr__` 会把 backbone 注册成子模块**
   —— 一开始 `dmem._model = model` 导致 `dmem.parameters()` 里冒出整个 766M backbone、
   `param_report` 报 "100.00%"。改成放进普通 dict。
2. **往 attention 模块上挂 `nn.Module` 会污染 backbone 的 `state_dict`**
   —— 会让 `save_pretrained` 把 δ-mem 权重写进模型文件。必须 `object.__setattr__`。
3. **引擎每次 `reset()` 都调 `set_attn_impl(model)`**，把 `_attn_implementation` 从
   `meowllm_dmem_meowllm_ar` 改回 `meowllm_ar` —— 现象是"写完记忆后 logits 差 0"。
   解决：模型最外层挂一个前向 pre-hook 把名字拉回来（`inject.install_guard`），
   写记忆那趟用 `bypass_impl` 让开。

## 4. r=64 怎么挂

### 4.1 参数与显存账（Qwen3-0.6B：d=1024, 28 层, 16 头 × 128, q_dim=2048）

每层参数：

```
W_q^m, W_k^m, W_v^m, W_β : 各 d×N·r = 1024×64 = 65,536
W_q^Δ, W_o^Δ           : 各 q_dim×N·r = 2048×64 = 131,072
每层合计 524,352  → ×28 层 = 14,681,856 ≈ 14.68M（实测一致）
```

| 配置 | 参数量 | 占 backbone | 状态/层 | 说明 |
|---|---|---|---|---|
| r=8 (=论文配比) | 1.84M | 0.24% | 64 float | 折算到 d=1024 太小，不建议 |
| r=16 | 3.68M | 0.48% | 256 | 保守 |
| r=32 | 7.35M | 0.96% | 1024 | 平衡 |
| **r=64** | **14.68M** | **1.95%** | **4096** | 本次目标（状态共 458KB fp32，显存可忽略） |
| r=64, N=4 (MSW) | 58.7M | 7.8% | 16384 | 参数有点重，先别上 |

**注意 r/d 的比例**：论文 8/2560 = 0.31%，0.6B 同比例只有 r≈3。r=64 是 **6.25%**，
是论文配比的 20 倍 —— 状态容量大了，但 `W_q^Δ/W_o^Δ` 占了 74% 的参数，
小数据上过拟合风险主要来自这两块。想压参数就把它们做成低秩：

```
Δq = W2 · (W1 r_t)   # W1: 64→16, W2: 16→2048，参数减半
```

### 4.2 必须先定标（这条是实测出来的）

初始化时 `w_dq/w_do` 的 std 是按解析估计定的，实际一测：

```
目标 |αΔq|/|q| = 8.0%     实测中位 0.356%     → 差 22 倍
```

因为 `|r_t| = |S qᵐ|` 取决于状态本身的大小（`|S| ~ 0.0025`），而状态大小又由写入门 β 和
写入段数决定 —— 纯解析估不出来。所以加了 `DeltaMem.calibrate()`：跑一次前向量出真实比例，
再把 `w_dq/w_do` 整体缩放到目标值。

**上线前一定要调一次 calibrate（或训完再存盘）**，否则 α=16 配随机初始化会把 logits 推得很狠
（实测 Δ 最大 2.13，足以改变话题走向）。

### 4.3 训练配置（可直接抄）

```bash
# 训练代码在 labs/dmem_train/（与推理侧分开，可整目录搬到云上）
cd labs/dmem_train
python build_data.py --mode llm --limit 20000        # 先生成数据
python train_sft.py --data data/sft.jsonl --preset presets/r64.yaml --out out
```

- 显存：batch=1、context 1024 时峰值 **1.7~4 GiB**（8GB 卡能跑到 context 2048）；
- 速度：本机约 **3.2s/样本**（两趟前向 + chunk 递推，10 步/121s），445 条/epoch ≈ 24 分钟；
- 写记忆吞吐：**0.23~1.16 ms/token**（1024 token 0.26~1.3s / 4096 token 0.9~4.7s，
  取决于 GPU 是否在boost），会话开始写一次完全没问题，每轮都写也可接受；
- 插入层：先全层（论文 §5.3 结论）。显存/过拟合吃紧时用 `--layers 8-19`（中间 12 层）。

### 4.4 配置项（建议加到 `config.yml` 的 `catbrain` 下）

```yaml
catbrain:
  delta_mem:
    enabled: false              # 先关着，训完再打开
    weights: .vendor/.MeowLLM/labs/dmem/out/dmem.safetensors
    rank: 64
    chunk: 16
    n_states: 1
    layers: all                 # 或 8-19
    alpha: 16
    calibrate_on_load: true
    # 写记忆的策略：会话开始 / 每 N 轮 / 话题切换
    write_on: session_start
    write_every_rounds: 8
    memory_source: [abmem, user_memory, recent_turns]
    max_write_tokens: 4096
    state_dir: character/memory/.dmem
```

### 4.5 上线路径（三步，可回滚）

1. **影子模式**（最安全）：正常走提示词，同时后台 `write_state` + 算一遍带 steering 的 logits，
   只记录 Δ 与 NLL 差，不影响输出。跑一天看差值是否稳定。
2. **替代 abmem 块**：把提示词里的 `abmem.build_prompt()` 那段文本换成状态 steering。
   同时保留 `ltmem` 原文兜底开关。
3. **全量**：角色卡 + 当前消息 + 状态。旧 abmem 降级成"写记忆的素材来源"。

### 4.6 风险与对策

| 风险 | 现象 | 对策 |
|---|---|---|
| 状态被噪声灌满 | 长时间会话后回复变模糊 | β bias 保持负值；只写"值得记的"（importance 过滤） |
| 小数据过拟合 | 训练 NLL 降、留出 NLL 反升 | ≥10k 样本；`--layers 8-19`；Δ 低秩化 |
| 写记忆太慢 | 0.23~1.16 ms/token（GPU 降频时慢 5 倍），每轮都写仍可能卡 | `write_every_rounds: 8`；M3 做 chunkwise 并行写（目标 <100ms/1k） |
| CUDA Graph 冲突 | 引擎开图捕获后状态写不进去 | 状态在生成期间冻结，天然只在图外更新 ✅ |
| 双流一致性 | thinker/writer 看到不同记忆 | 两行共用同一个 state（已支持 batch=2 广播） |

## 7. 训练算力与云上落地

本地 8GB 卡能训（已实测，context 1024 峰值 ~4GiB），但只够验证。正式训 1 万条用云卡：

| 项 | 你的云实例 | 够不够 |
|---|---|---|
| RTX 5090 32GB | 0.6B 全参 bf16 只占 1.2GB，δ-mem 0.06GB | **远超需求**：context 可提到 4096、`accum` 提到 16，或直接换 4B backbone（论文配比） |
| 25 vCPU / 92GB RAM | 数据预处理 + DataLoader | 够；CPU 只在 tokenize 时忙 |
| 系统盘 30GB | 模型 1.4GB + 权重 | 够，但**权重和数据必须放数据盘**（`/root/autodl-tmp`） |
| 数据盘 50GB | Qwen3-0.6B 1.4GB + 20k 样本（~200MB） | 够；换 4B 会占 8GB 也够 |
| PyTorch 2.8.0 + CUDA 12.8 | 5090 是 sm_120，需要 cu128 | **匹配**（本机是 2.11+cu128，同代） |
| ¥2.78/时 | 1 万条 ≈ 6~9 小时 | 约 ¥25 一次，可接受 |

注意两点：
1. **不用挂模型/不用存整个模型**。δ-mem 参数只有 14.68M，产物是一个
   `dmem.safetensors`（约 56MB，fp32），backbone 权重不动、也不重存。
2. transformers 版本对齐：`transformers==5.3.0`（本机验证过的就是它），
   别让 pip 升到最新；双流引擎的注意力派发表依赖它。
`labs/dmem_train/setup_autodl.sh` 是一键装环境 + 拉模型的脚本。

## 8. 数据能不能让 AI 自己填

能，而且**必须**用 AI 填（人工写不出 1 万条）。但有个硬约束：**答案只能从 context 推出**，
否则相当于没训。所以不是"让 AI 自由编对话"，而是三个受控的合成任务：

| 任务 | 提示词要点 | 产物 | 占比 |
|---|---|---|---|
| 单跳改写 | 给 6 条记忆，挑 1 条，写成"主人自然口语提问 + 40 字内答案"，不足则输出 null | (query, response) | 50% |
| 多跳组合 | 给两条相关记忆，要求答案必须**同时**用到两条 | 同上 | 20% |
| 时间/否定 | 给带日期的记忆，问"上周三说的"；或问记忆里**没有**的事，答案应是"没聊过" | 同上 | 20% |
| 闲聊锚点 | 不给记忆，让 AI 用角色卡口吻回答 | 保住通用能力的负样本 | 10% |

`build_data.py --mode llm` 已经实现了第一种（批 6 条 → 1 个问答对，多线程）；
二/三类只需要换 `LLM_PROMPT`，骨架现成。**关键检查**：抽 50 条人工看一眼，
如果"把 context 删掉模型也能答"，这条数据就是废的（可以自动筛：no-context NLL 明显低
于 with-state NLL 的样本丢掉）。

AutoDL 侧不需要找"现成数据集"：AutoDL 提供的是公共数据集挂载（`/autodl-pub`）与学术加速
（[公共数据文档](https://private.autodl.com/docs/practice_3/)、[公开数据 API](https://api.autodl.com/docs/public_data/)），
里面没有对口的"中文角色扮演 × 长期记忆"数据；能和论文对齐的只有
HotpotQA / LoCoMo / MemoryAgentBench，那是**评测**用的，不是训练用的。
真数据只能从你自己的 `character/abstract_memory` 长出来。

## 9. 一句话总结

数学部分很小（5 组式子、4 个模块），工程量全在**注入点**和**数据**上：
注入点已经用 "RoPE 线性性 + 派发表包装 + 守护 hook" 打通（能直接跑在你的双流引擎上，不用改引擎代码）；
数据是本项目唯一的真瓶颈 —— 439 条记忆事件要扩到 1 万条以上，且必须坚持
"context 从输入里删掉、只留状态"这个训练约定，否则训不出记忆通路。
