# 衰减做出来之后，怎么测才算"权威准确"

> 衰减是最容易"静默改坏记忆"的功能：数值上一切正常、loss 也没炸，
> 但模型就是开始忘事或者记错事。所以**先写测试，再写实现**（TDD），
> 并且测试要分三层：公式层（确定性）、数值层（曲线）、行为层（会不会忘事）。

---

## 0. 先把"正确"定义成可证伪的命题

| 命题 | 说法 | 怎么证伪 |
|---|---|---|
| **P1 单调性** | 同一段记忆，距今天数越大，对输出的影响越小 | 测 Δlogits(t) 是否单调递减 |
| **P2 半衰期保真** | 实测半衰期 == 设定半衰期（误差 <10%） | 指数拟合恢复 λ，和配置比 |
| **P3 复合律** | 衰减 a 天再衰减 b 天 == 一次衰减 a+b 天 | `λ^a·λ^b == λ^(a+b)` |
| **P4 幂等** | 同一天衰减两次 == 一次 | `last_decay_at` 生效 |
| **P5 不损伤** | 近期事实在衰减后不退化 | with-state NLL 不升 |
| **P6 会遗忘** | 远期低重要度事实确实淡出 | 时间锚定评测集上的正确率按设计下降 |

**P5 和 P6 是一对**，只测一个必然自欺：只测 P5 会做出"永不遗忘"（等于没做衰减）；
只测 P6 会做出"什么都忘"（记忆功能被衰减吃掉）。

## 1. 公式层：确定性单测（`labs/dmem/test_decay.py`）

不需要 GPU、不需要模型、毫秒级。**这是唯一能 100% 判定对错的层。**

```python
① 单维精确性
   S = 随机 (N,r,r)，λ_day 给定，Δdays=7
   断言  S_after ≈ S * λ_day**7            # 逐元素，fp32 容差 1e-6

② 复合律 P3
   a=3,b=11  →  λ**(3+11) == λ**3 * λ**11  # 单调性之外，防"实现里四舍五入天数"

③ 幂等 P4
   同一 last_decay_at 调两次 → 第二次必须是恒等变换（S 逐位不变）
   且第二次不能改 last_decay_at

④ 逐维半衰期
   half_life 是向量 [7,30,180,365] 时，断言每行的衰减比例各自正确
   （这对应 MSW 子状态分工：事实/近事/情绪/任务各自半衰期）

⑤ 下限钳制
   λ 有下限（如 0.98/天）时，断言 Δdays=10000 也不会衰减到 0
   且不会产生 NaN / 下溢（检查 (S==0).any() == False）

⑥ 时钟边界
   Δdays = 0（同一天）、负数（时钟回拨）、超大值（>10 年）
   → 0 和负数必须是恒等；超大值不能炸
```

**这一层的纪律**：任何一条不过，就不许进下一层。因为公式错的话，
后面两层的现象会被误读成"模型问题"。

## 2. 数值层：衰减曲线与半衰期拟合（`labs/dmem/bench_decay.py`）

目的：验证 **P1 单调性** 与 **P2 半衰期保真**，也就是"衰减真的作用到了输出上，
而且强度等于设定"。

```
准备：
  固定 seed、固定 tokenizer、greedy、temperature=0、fp32 取 logits
  一段固定 prompt（同一个 query），一批固定记忆（比如 50 段事件）

做法：
  for days in [0, 3, 7, 14, 30, 60, 90, 180, 365]:
      写记忆 → 施加 Δdays 衰减 → 算 logits
      记录 effect(days) = || logits(days) − logits(无记忆) ||   # 或 max|Δ|
      每个 days 重复 3 次（不同 seed 的记忆顺序），报 mean ± std

判定：
  * 单调性：effect(days) 严格递减（容许 1 个局部抖动），Spearman ρ < −0.9
  * 拟合：  对 effect(days) 做 log 线性回归，恢复 λ_est = exp(slope)
            断言 |λ_est − λ_set| / λ_set < 0.10
  * 端点：  effect(0) 显著 > 0（衰减前有影响）；effect(365) 显著 < effect(0)
```

⚠ **三个必须做的控制**（否则结论不可信）：

1. **不要复用同一个 state** 测不同 days —— 读会污染。每次从「原始状态」重新拷一份再衰减。
2. **bf16 噪声**：状态是 fp32 但模型是 bf16，`max|Δ|` 的地板约 0.05 量级。
   先测"两次完全相同的输入"的 Δ 作为**噪声基线**，只信显著高于它的差异。
3. **算力漂移**：同一数据在 GPU 降频/boost 下 kernel 不同可能改变末位。
   所有比较都在同一次进程内、连续执行。

## 3. 行为层：时间锚定评测集（`labs/dmem/eval_decay_anchor.py`）

**唯一能回答"它到底会不会忘事"的测试**，也是最容易被自己骗的一层。

### 3.1 构造方法（关键：成对）

对每条样本构造**同一个 query，三种"记忆年龄"**：

| 条件 | 状态 | 期望 |
|---|---|---|
| `recent` | 事实在"昨天"写入，不衰减 | 正确率最高 |
| `aged_30` | 同一事实，衰减 30 天 | 与半衰期匹配的下降 |
| `aged_365` | 同一事实，衰减 365 天 | 明显下降（低重要度）/ 保持（高重要度） |

以及两个对照臂：

- `no_memory`：不写状态（下界）
- `no_decay`：写状态、不衰减（上界）

### 3.2 指标

不是"看几条回复像不像"，而是四个数：

| 指标 | 定义 | 期望 |
|---|---|---|
| `acc_recent` | 近期事实正确率 | ≥ `acc_no_decay` − 2%（**不损伤** P5） |
| `acc_aged` | 远期低重要度正确率 | 显著低于 `acc_recent`（**会遗忘** P6） |
| `acc_aged_important` | 远期**高**重要度 | ≥ `acc_recent` − 5%（保护机制生效） |
| `nll_gap` | `no_memory NLL − with_state NLL` | 远期仍 > 0（残余信息为正） |

### 3.3 统计纪律（0.6B 方差很大，必须做）

- 每格样本 **≥200 条**，否则 1~2 个点的差异没有意义；
- 每个条件跑 **≥3 个 seed**（记忆顺序/sampling），报 `mean ± std`；
- 条件之间用**配对检验**（同一 query 的 A/B 成对）：
  McNemar（正确率）或 bootstrap 95% CI（NLL）；
- **不要**用"某一次跑出来更好"当结论。

### 3.4 防泄漏检查（最容易翻车的地方）

时间锚定评测集必须验证：**远期事实在近期会话里也没被提过**。
做法：对每条 `aged_365` 样本，检查 fact 关键词是否出现在 `recent` 段里；
出现就剔除（否则你测的其实是"近期记忆"）。

## 4. 反例测试（专门防"衰减过头"）

| 用例 | 做法 | 期望 |
|---|---|---|
| 高重要度保护 | importance=5 的事实衰减 365 天 | 仍能答对 |
| 重复强化 | 同一事实分 5 次写入后衰减 90 天 | 强于单次写入后衰减 90 天 |
| 冲突更新 | "搬家了"A→B，衰减后问住哪 | 答 B（新事实赢） |
| 极端序列 | 连续 365 次（每天一衰减） | 无 NaN、无 0、|S| 不爆 |
| 空状态 | 从未写过就衰减 | 恒等，不报错 |

## 5. 固化成回归闸门（CI）

三个脚本、六个命题，任何一条超阈值就 fail：

```bash
python labs/dmem/test_decay.py         # 公式层，必须 100% 过
python labs/dmem/bench_decay.py        # 数值层，半衰期误差 <10%
python labs/dmem/eval_decay_anchor.py  # 行为层，acc_recent 不退化 + acc_aged 按设计降
```

闸门阈值建议（写进脚本，别靠人记）：

```
P1 单调性    Spearman ρ ≤ −0.9
P2 半衰期    |λ_est − λ_set| / λ_set ≤ 0.10
P3 复合律    逐元素误差 ≤ 1e-6
P4 幂等      逐位相等
P5 不损伤    acc_recent ≥ acc_no_decay − 0.02
P6 会遗忘    acc_aged ≤ acc_recent − 0.15（低重要度）
     且      acc_aged_important ≥ acc_recent − 0.05
```

## 6. 五个常见假阳性（都会让你以为"衰减生效了"）

1. **数值地板当效果**：bf16 的 logits 抖动本来就有 0.05，把 0.06 的差当成衰减。
   → 必须先测同输入两次的噪声基线。
2. **状态被复用**：同一个 `dmem.states` 上反复测不同天数，前一次的残留让曲线看起来"平滑"。
   → 每次从原始状态深拷贝。
3. **忘了重置 `last_decay_at`**：一天内被衰减 N 次，看起来衰减超强。
   → P4 幂等单测专门钉这个。
4. **只测 logits 不测行为**：曲线完美，但模型该记住的还是记不住（因为 Δq 的
   方向被衰减改了符号/方向，而不是幅度）。
   → 行为层不可省。
5. **评测集泄漏**：所谓"365 天前的事"在近期又被提过一次。
   → 第 3.4 节的实体检查。

---

## 7. 顺序建议（做完衰减的当天就能跑）

1. 先写 `test_decay.py`（30 分钟，纯 CPU）→ 公式对不对；
2. 再写 `bench_decay.py`（1 小时，单卡）→ 强度对不对；
3. 最后写 `eval_decay_anchor.py`（半天，主要花在造集）→ 行为对不对；
4. 三个全绿之后，才允许把 `enabled: true` 挂到线上，并且先影子跑一天。
