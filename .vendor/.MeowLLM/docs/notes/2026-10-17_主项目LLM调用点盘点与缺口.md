# 主项目 LLM 调用点盘点 & 接入 MeowLLM 的缺口

> 扫描范围：`D:\.Meowlisis`（排除 `.vendor/.MeowLLM`）
> 结论：主项目用**端口-适配器**模式，每个功能域一套 `port/{aliyun,deepseek,gemini}.py`，
> 全部通过 `OpenAI(api_key=..., base_url=...)` 构造，由配置里的 `llm_type` 选择实现。

**共同形态**（以 `func/llm/port/deepseek.py` 为例）：

```python
self.base_url = self.config.deepseek_base_url
self.client = OpenAI(api_key=self.api_key, base_url=self.base_url)
```

→ **改成 MeowLLM 只需把 `base_url` 指向 `http://127.0.0.1:18100/meowllm/v1`**，无需改代码。
但前提是 MeowLLM 要满足它们实际用到的接口能力。

## 2. 接口能力矩阵：主项目用什么 vs MeowLLM 有什么

| 能力 | 主项目是否用 | MeowLLM 现状 | 缺口 |
|---|---|---|---|
| `/chat/completions` 非流式 | ✅ 全部 | ✅ | — |
| `stream: true` | ✅ `llm.*.stream` 配置项 | ✅ SSE | — |
| **`system` 角色** | ✅ 几乎所有域的第一条消息 | ⚠️ `render_chat` 支持，但**没有配置级默认 persona** | **需加 `system_prompt`** |
| `temperature` / `top_p` | ✅ | ⚠️ 需确认是否透传到采样 | 需核对 |
| `max_tokens` | ✅ | ✅ | — |
| **`tools`（function calling）** | ✅ `func/toolbox/` | ❓ **dualstream 引擎未验证** | **需确认/实现** |
| `tool_choice` | 可能 | ❓ | 需确认 |
| **`/embeddings`** | ✅ `func/database/store/` | ❌ 没有该路由 | **需加，或保留云端 provider** |
| **多模态（image_url）** | ✅ `llm_active.vision` / `meowvision` | ❌ 未实现 | 需加，或保留云端 |
| `enable_thinking`（阿里云专有） | ✅ | ❌ 不认 | 需映射到 `thinking_level` |
| `reasoning_content` 分离 | ❓ 项目可能不读 | ✅ 双流输出 | 项目侧需接入才能受益 |

## 3. 接入前必须补的三件事

### ① `system_prompt`（你已提出，优先级最高）

现状：角色设定只能塞进第一条 `user` 消息。

需要：
- `config.yml` 增加 `engine.dualstream.system_prompt`（默认空）
- 或请求级 `meowllm.persona` / 直接吃 OpenAI 的 `system` 消息（已有基础）
- 渲染进 **PERSONA 块**（独立块，不随对话变化）→ 也为后面的"跨请求 KV 复用"打基础

### ② `tools` / function calling

`func/toolbox/` 是主项目的核心能力之一。**dualstream 引擎目前没有工具调用实现**（之前的 llamacpp 引擎有）。
两条路：
- **A**：MeowLLM 内实现 OpenAI `tools` 协议 → 解析成文本注入 prompt，返回 `tool_calls`
- **B**：工具调用**继续走云端**（`toolbox.*` 保持 deepseek/aliyun），只有纯对话走本地

**建议先 B**：角色扮演/快速回复不需要工具，先把主对话跑通。

### ③ `enable_thinking` 映射

主项目配置里有 `llm.*.enable_thinking`。MeowLLM 应接受该字段并映射：
```
enable_thinking=false -> 关闭思考流（只出 writer）
enable_thinking=true  -> 双流
```
这样主项目不用改代码就能控制。

## 4. 分期接入建议

| 阶段 | 范围 | 前提 |
|---|---|---|
| **P0** | `func/llm/`（主对话）指向 MeowLLM | ① system_prompt + ③ enable_thinking |
| **P1** | `func/llm_active/`（主动对话） | 同 P0 |
| **P2** | `catbrain/*`（记忆/价值观） | 只需 chat，直接可用 |
| **P3** | `meowsinger` / `psyche` / `database.search` | 直接可用 |
| **P4** | `toolbox` / `meowvision` / `flux_painter` | 需 ② tools 或保留云端 |
| **不进** | `database.store`（embedding） | MeowLLM 不做 embedding，保留云端 |

**接入方式（不改项目代码）**：
```yaml
llm:
  local_llm_type: deepseek          # 复用哪个 port
  deepseek:
    base_url: http://127.0.0.1:18100/meowllm/v1
    api_key: meowllm                # 占位
    model: meowllm-local
```

## 5. 风险点

1. **主项目不读 `reasoning_content`** → 双流能力用不上，只会拿到 writer 的 `content`。要吃到 AsyncReasoning 的收益，主项目侧需要改渲染（或至少把思考日志打出来）
2. **超时**：8B 单步 90 ms，长回复可能几十秒；主项目若设了 30s 超时要调
3. **并发**：主项目多个域可能同时调 LLM，本地单卡会串行化 → 需要 P2-1 的 batch 合并
4. **embedding 缺失**：`database.store` 必须继续用云端
