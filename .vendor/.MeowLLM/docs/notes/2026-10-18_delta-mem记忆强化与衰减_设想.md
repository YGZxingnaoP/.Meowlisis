# 头脑风暴：把 δ-mem 的记忆做成"会用进废退"的（**不实施**）

> 前提：`mem0` 现在的逻辑是"记一条 → 检索 → 塞回提示词"，没有"用得多的更牢、
> 不用的慢慢淡掉"。δ-mem 的状态矩阵天然带三个旋钮，可以把这套半衰期/强化逻辑
> 直接做进数学里，而不是做在"文本条目"上。
> **本文只讨论，不动代码。**

---

## 0. 先看 δ-mem 给了哪三个旋钮

```
S_t = Diag(λ_t) S_{t−1} + Diag(β_t) (v_t − S_{t−1} k_t) k_tᵀ        λ = 1 − β
r_t = S_{t−1} qᵐ_t
q̃   = q0 + α Δq,   ỹ = a + α Δo
```

| 旋钮 | 物理含义 | 现有代码里在哪 | 现实对应 |
|---|---|---|---|
| `β_t ∈ (0,1)^r` | 这条记忆写多强 | `w_beta` 的 bias 初值 `-2.0` | 这件事有多重要 / 情绪多强 |
| `λ_t = 1−β_t` | 旧记忆留多少 | 同上（绑在一起） | 遗忘速度 |
| `α` | 读出来用多大力 | 每层一个可学标量 | 这件事对当下有多相关 |

关键洞察：**`β` 和 `λ` 被强制绑成 `λ=1−β` 是论文的设计**，但对"真人式记忆"来说，
"写得多强"和"忘得多快"应该是**解耦**的 —— 一次情绪冲击很强但会很快淡；
一个反复确认的偏好写得不强但永远不该忘。所以第一个建议就是把它拆开。

---

## 1. 四个可做的点子（按性价比排序）

### 1.1 显式时间衰减（最便宜，几乎零风险）

delta 规则的 `λ^Δt` 本身就等价于指数衰减：一条连续时间衰减可以**离线一次算完**，
不需要回放记忆：

```
S ← diag(λ_day ** Δdays) · S        # 每层每 owner 一次，O(r²)
```

- 与现有配置对齐：`abstract_mem.evidence.disp_half_life_days=180`、
  `rein_half_life_days=30` → `λ_day = 0.5 ** (1 / half_life)`。
- 收益：**"你三年前说过的一次性事情"会自然淡掉**，而不是永远占着状态容量。
- 风险：非常低。唯一的坑是同一天反复衰减（要记录 `last_decay_at`）。
- 成本：一次 28×64×64 的乘法，微秒级。

### 1.2 写入强度 β 由事件元数据调制（中等）

现在 β 完全由隐状态决定（`σ(W_β x + b)`），等于"模型自己判断这句话值不值得记"。
但你的 `abstract_memory` 里已经有现成的信号：

```
importance ∈ [0,5]    accuracy ∈ [1,5]    tags/topics    出现次数（去重后）
```

建议：

```
β_bias_i = b0 + w_i · [importance, accuracy, |emotion|, 重复次数]ᵀ
```

即**同一个 `w_beta`，但 bias 按事件走**。这样：
- 高 importance 的事一次就写牢（β≈0.9）；
- 随口一句只写一点（β≈0.1），下次提到再补 —— delta 规则的残差会自动"只补差额"，
  这正是它比"存文本+检索"优雅的地方：**重复提同一件事不会重复占容量，只会更准**。

### 1.3 读强化（最有"真人感"，也最难）

真人记忆是**每次回忆都会加固**（reconsolidation）。δ-mem 的读是 `r_t = S qᵐ_t`，
读完可以顺手写回一次：

```
S ← S + η · (r_t − S qᵐ_t) (qᵐ_t)ᵀ        # η 很小，如 0.05
```

读的越多，那条关联越被"压实"。

- 但要注意：这会让**推理变成有状态且不可逆的**（同一句话读两次结果不同），
  与你引擎里"生成期间状态冻结"的约定冲突 → 只能放在**轮次结束后**做一次批量回写，
  不能放在 decode 每步里（会破坏 CUDA Graph 与可复现性）。
- 还有一个坑：w_dq 会让"读"偏向那些**已经影响输出**的记忆，形成正反馈（越用越用）。
  需要给 η 设上限，或者只在"被引用到"时才回写（用输出文本里是否出现该记忆的关键词做门）。

### 1.4 干扰与保护（结构层面）

现在所有东西挤在一个 `r×r` 里，靠 `β` 逐维竞争。真人有"工作记忆 / 情景记忆 /
语义记忆 / 情绪记忆"的分层。MSW 的 `N` 个子状态正好可以分工：

| 子状态 | 放什么 | 衰减 |
|---|---|---|
| S¹ | 事实/偏好（"主人不吃香菜"） | 极慢（半衰期 1 年） |
| S² | 近期事件（"昨天在调混响"） | 快（7 天） |
| S³ | 情绪/关系（"今天被骂了，不爽"） | 中（30 天），且读的时候权重高 |
| S⁴ | 任务进度（"国庆前把唱歌调好"） | 到完成就清零 |

代价：`N=4` 时参数从 14.68M 涨到 58.7M（每层多 4 组投影）。**这是唯一需要重新训练的一条**，
前三条都能在已训好的权重上直接改。

## 2. 一个可落地的打分公式（把上面的收成一行）

以下三种情况按"写入时的初始强度"算：

```
strength_i = importance/5 * (1 + 0.3*|emotion|) * recency_boost
β_i        = sigmoid(logit(strength_i) + (W_β x)_i)
```

衰减时（每天一次）：

```
λ_i = 0.5 ** (1 / half_life_i)          half_life_i 来自子状态分工
S   ← diag(λ_i ** Δdays) S
```

强化时（每轮结束，只在"被引用"时）：

```
S ← S + η · (v_observed − S k_topic) k_topicᵀ     # 用这一轮的真实内容当 v
```

这三步加起来就把"重要的一次就记住、随口的一句慢慢淡、常提的越记越牢"表达完了，
而且**全是矩阵乘法，不需要额外存储**。

## 3. 和现有 `cat_values` / `evidence` 打分怎么统一

你现在已经有两套打分：

| 位置 | 指标 | 现状 |
|---|---|---|
| `abstract_mem.evidence` | 强化半衰期 30 天 / 消散半衰期 180 天 / `same_delta=0.5` / `opposite_delta=1` | 在**文本条目**上算 |
| `cat_values` | 价值观、情绪 | 在提示词里现算 |

建议：**让 evidence 的打分继续管"文本条目"，只把结果当作 β 的输入**，不要重写一遍。
即 `importance` 已经含了"置信度+强化次数"，δ-mem 只需要消费它。
这样两套系统不会打架，而且 abmem 侧一行代码不用改。

## 4. 风险与验证方式

| 风险 | 表现 | 怎么防 |
|---|---|---|
| 不可解释 | 想不起"它为什么提起这件旧事" | 保留 `/control/dmem/status` 的写入日志（谁、何时、多少 token、importance） |
| 正反馈漂移 | 越常用的记忆越强势，最后只会聊那几个话题 | 读强化加 η 上限 + "被引用才回写" |
| 衰减过头 | 一周没聊天就全忘了 | 衰减只在 `last_decay_at` 之后按天算一次，且设 λ 下限（如 0.98/天） |
| 与文本记忆打架 | 提示词里说 A，状态里说 B | 影子模式先比对，冲突时以提示词为准（提示词是显式的，状态是隐式的） |
| 训练/推理不一致 | 衰减后 β 分布偏移 | 衰减只动 S 的范数，不改 β 的分布；训练时随机注入衰减因子做增强 |

验证方式（都能量化）：
1. **留出集 NLL**：衰减策略不同，看 with-state NLL 是否保持；
2. **旧事回忆率**：构造"30 天前的事实"评测集，看会不会淡掉；
3. **话题多样性**：统计连续 50 轮的话题熵，防止正反馈收敛；
4. **人审 20 条**：抽"提到很久以前的事"的回复，看像不像真人。

---

## 5. 建议的落地顺序（如果哪天要做）

1. **λ^Δdays 显式衰减**（1 处改动，10 行，零风险，先上）；
2. **β bias 由 importance 调制**（要重训一次，但只是 bias，不用改结构）；
3. **读强化**（要动会话生命周期，放轮次结束，不能进 decode）；
4. **MSW 子状态分工**（重构 + 重训，收益最大也最贵，最后做）。

前两条做完，"真人感"其实已经出来了：**重要的记得牢、随口的一句会淡、常提的越来越准**。
第三条要小心，第四条是另一个量级的工程。
